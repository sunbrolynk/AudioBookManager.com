---
title: Audiobookshelf 連線
description: 把 ABM 連線到你的 Audiobookshelf 伺服器。
---

Audiobookshelf（ABS）是你用來聽書的伺服器。在 **Settings > Audiobookshelf** 裡把 ABM 連上去，電腦和手機上都能用。你要填伺服器位址，以及為某個 ABS 使用者建立的 API 金鑰。

## 連線

- **Enable:** 讓 ABM 使用這台伺服器。開著它儲存時，ABM 會先檢查伺服器，如果有錯誤等級的檢查沒通過，就拒絕儲存，頁面會告訴你原因。關著儲存的連線不會被檢查。
- **Server address:** 你的 ABS 伺服器回應的位址，例如 `http://192.168.1.20:13378`。如果 ABS 和 ABM 跑在同一台機器上，就用這台機器的區域網路位址；如果兩者都在 Docker 裡，就用容器名稱或 IP。
- **API key:** ABS 裡 admin 使用者的 API 金鑰。
- **Verify TLS certificate:** 預設開啟。如果你的伺服器用的是你自己的憑證授權單位簽發的憑證，就在 **CA bundle path** 裡填它的 CA 套件路徑，不要關掉驗證。路徑留空就用系統的憑證。
- **Test:** 用畫面上現有的內容跑檢查，不儲存任何東西。
- **Disconnect:** 先讓你確認，然後刪除已儲存的位址和金鑰。

## ABM 如何連到 ABS

ABM 總是直接連 ABS，從不經過你在 [Network](/settings/network/) 裡選的 VPN 或代理。位址在儲存前會被檢查，不安全的會被拒絕。指回 ABM 所在機器本身的位址、連結本地位址和雲端中繼資料位址會被拒絕，解析到這些位址的名稱也一樣。你自己的區域網路位址沒問題，所以同一台機器上的 ABS 需要用這台機器的區域網路位址，或是它的容器名稱或 IP。

## API 金鑰

金鑰加密儲存，之後不會再顯示。儲存或測試時留空，就保留已儲存的金鑰。已儲存的金鑰只會送到儲存時對應的位址，所以如果你改了位址、Verify TLS 或 CA 套件，要重新輸入金鑰。如果 ABM 再也讀不了已儲存的金鑰（加密金鑰遺失或變了），即使連線是關著的，這個頁面也會顯示和其他設定頁面一樣的提示，要你重新輸入。

## 檢查什麼

**版本。** ABM 需要 ABS 2.37.0 或更新，並在 2.37.2 上測試過。更舊的伺服器，或是沒回報 ABM 看得懂的版本的伺服器，會出錯。更新的會給出警告，因為 ABM 沒在上面測試過。

**帳號。** API 金鑰屬於某個 ABS 使用者，ABM 會檢查這個使用者。

- **出錯，直到修好：** 使用者必須是 admin 或 root，並且有 Update 權限，以及對所有資料庫、所有標籤和成人內容的存取權限。
- **警告，照樣儲存：** Upload 關著（ABM 沒辦法管理封面），或是 Delete 關著（你在 ABM 裡刪掉的書會留在 ABS 裡，直到你打開它）。

## 狀態

Status 區塊顯示上次檢查的結果（Not connected、OK、Warning 或 Error）、伺服器版本、金鑰所屬的使用者、ABM 上次檢查的時間，以及各項檢查。沒通過的檢查會顯示原因，通過的只計數。

連線開著時，[System > Status](/system/status/) 裡也有一列 Audiobookshelf。它在你儲存時更新，也由每 6 小時執行一次的定期健康檢查更新，所以不是每次開啟頁面都即時探測。關著的連線在那裡保持安靜，就算它已儲存的金鑰讀不了。連線開著時，ABM 再也讀不了的已儲存金鑰會顯示為錯誤，直到你重新輸入，還沒檢查過的連線顯示為警告。

## ABM 會刪掉什麼

ABM 在 ABS 裡只會刪掉項目紀錄，從不永久刪除檔案。
