Audiobookshelf（ABS）是你用來聽書的伺服器。ABM 透過伺服器網址和為某個 ABS 使用者產生的 API 金鑰連線它。

## 版本

ABM 需要 ABS 2.37.0 或更新版本，並在 2.37.2 上測試過。更舊的伺服器會被拒絕。更新的版本會給出警告，因為 ABM 沒在它上面測試過。

## 帳號

API 金鑰屬於某個 ABS 使用者。儲存或測試時，ABM 會檢查這個使用者。

- **修好之前會被拒絕：** 該使用者必須是 admin 或 root，並且要有 Update 權限，以及存取所有資料庫、所有標籤和成人內容的權限。
- **會警告，但仍然儲存：** Upload 關閉（ABM 無法管理封面），或 Delete 關閉（你在 ABM 裡刪除的書會留在 ABS，直到你打開它）。

## ABM 如何連到 ABS

ABM 一律直接連線 ABS，從不經過你在 [Network](/settings/network/) 裡選的 VPN 或代理。伺服器網址在儲存前會被檢查，不安全的網址會被拒絕。

## API 金鑰

金鑰以加密方式儲存，之後不會再顯示。儲存或測試時留空，就會沿用已儲存的金鑰。已儲存的金鑰只會傳送到儲存時對應的網址，所以如果你改了網址、TLS 設定或 CA 套件，請重新輸入金鑰。

## 驗證 TLS

憑證預設會被驗證。如果你的伺服器用的是你自己的憑證授權單位簽發的憑證，請填它的 CA 套件路徑，而不是關掉驗證。

## Test 和 Disconnect

**Test** 在不儲存的情況下檢查伺服器：版本、使用者權限和它的資料庫。儲存一個已開啟的連線時，會先做同樣的檢查，只要有錯誤項失敗就會被拒絕。儲存為關閉的連線不會被檢查。**Disconnect** 會移除已儲存的連線和它的金鑰。

## System Status

連線開啟後，[System > Status](/system/status/) 會有一列 AudioBookShelf，顯示上次檢查的結果。它在儲存時重新整理，也由每 6 小時執行一次的定期健康檢查重新整理，所以不是每次開啟頁面都即時探測。

## ABM 會刪除什麼

ABM 只會在 ABS 裡移除項目記錄，絕不會徹底刪除檔案。
