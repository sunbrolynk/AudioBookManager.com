**Settings > Metadata > Source** には、3 つの選択肢がある **Metadata Source** 設定があります。選ぶまでは Built-in です。

| 選択肢 | 意味 |
|---|---|
| Built-in（デフォルト） | Libex が ABM の中で動きます。先に外向きの接続を選んでおく必要があります。 |
| <span class="nowrap">Hosted ([LibexDB.com](https://libexdb.com) <a href="https://github.com/LibexHQ/Libex" aria-label="GitHub の Libex"><Icon name="github" size="1em" class="inline-icon" /></a>)</span> | ABM が公開 Libex インスタンスに問い合わせます。 |
| Self-hosted | ABM が指定した Libex サーバーに問い合わせます。**Server URL** を入力します（例：`http://192.168.1.20:8000`）。 |

**Test** は選んだ取得元を保存せずにチェックします。**Status** は準備ができているかどうかを表示します。別の取得元を選ぶと、保存するまで **Status** に「Not in use yet - save to switch」と表示されます。

## 内蔵と外向きの接続

Built-in は自分のマシンから Audible と通信するので、**Settings > General > Proxy & VPN** を使います。経路はそのページで決めます。プロキシ、内蔵の WireGuard トンネル、自分の VPN コンテナ、または承知のうえでの直接接続です。何も選んでいないと自動の問い合わせはブロックされ、その旨が表示されます。選んだ経路が落ちている場合もブロックされます。自分のアドレスにフォールバックすることはありません。Direct を選ぶと、Audible から自分の IP アドレスと ABM が調べた本が見える、という警告が出ます。

どの取得元も、問い合わせは **Settings > Network** で選んだ接続を通して送られ、ほかの経路に切り替わることはありません。LAN 上の self-hosted サーバーと、そこが配信するカバーには直接つながります。

## ホスト型とセルフホスト

この2つでは、ABM が Libex サーバーに問い合わせ、そのサーバーが Audible と通信します。セルフホストの URL は保存前にチェックされ、空のものや安全でないものは拒否されます。サーバーが落ちている場合は、その名前付きで「メタデータの取得元が使えない」と報告されます。

## 取得元に届かないとき

取得元に届かない、または ABM が拒否されると、多数の項目に対する更新・インポート・同期は、本ごとに失敗するのではなく止まります。1 回のタイムアウトはその項目だけをスキップします。通知は障害の種類ごとに 1 件届きます。エラーメッセージには取得元と本当の理由(たとえば VPN が落ちている)が入ります。

Libex が ABM にペースを落とすよう求めると、待っている検索は約 10 秒であきらめ、バックグラウンドタスクは最大 2 分待ちます。

## どれを選ぶか

- とにかく動いてほしくて、Audible にアドレスを見られてもかまわない：直接接続の Built-in、または Hosted。
- Audible に IP を見せたくない：プロキシ、内蔵の WireGuard トンネル、または別の VPN コンテナやサービスを経由する Built-in。もしくは Hosted で、この場合は自分ではなく Libex サーバーが Audible と通信します。
- すでに Libex サーバーを動かしている：Self-hosted。
