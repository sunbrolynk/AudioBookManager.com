책 상세 페이지에는 Libex가 가진 챕터와 실제로 파일에 들어 있는 챕터가 나란히 나와요. 기준은 Libex예요. 이 화면은 내 파일에 Libex가 말하는 챕터가 제대로 들어 있는지를 알려 줘요.

## 비교 읽는 법

Libex 챕터마다 아이콘과 단어로 된 배지가 붙어요:

- **Matches**: 파일 안의 챕터가 2초 안에서 시작하고, 대소문자, 악센트, 양끝 문장 부호를 빼면 제목이 같아요. "Chapter 1"과 "Chapter One"은 다른 제목이에요.
- **Differs**: 제목이 다르거나, 제목은 근처에 있지만 시작이 2초 넘게 차이 나요.
- **Missing**: 짝이 되는 파일 안 챕터가 없어요.
- **Extra**: 어떤 Libex 챕터와도 짝이 되지 않는 파일 안 챕터예요.

여러 파일로 된 책은 파일 이름 순서로 하나의 타임라인에 이어 붙여요. 파일을 넘어 "(cont.)"로 이어지는 챕터는 하나의 챕터로 읽어요. Libex에 연결할 수 없으면 파일 안 챕터 목록과 이유를 적은 한 줄이 보여요. 페이지가 오류를 내는 일은 없어요.

## 판본이 다를 때

Libex의 시간 정보는 그 데이터가 설명하는 판본에만 맞아요. 내 오디오 길이가 Libex와 15초 또는 0.5% 중 큰 쪽보다 더 차이 나면 경고가 뜨고, **Update**와 **Create .cue**가 모두 막혀요. 이걸 무시하는 옵션은 없어요.

## 파일 안 챕터 업데이트하기

모든 오디오 파일의 챕터를 Libex 챕터로 바꿔요. [변환 큐](/ko/using/conversions/)에서 다시 인코딩 없이 챕터 작업으로 돌아가요. 비교 결과가 "differs"이거나 "no embedded chapters"일 때만 나와요.

- 파일마다 임시 파일로 다시 쓰고, 확인한 다음, 바꿔 넣어요. 확인 조건은 이래요: 읽을 수 있어야 하고, 원본보다 0.5초 또는 1% 넘게 짧지 않아야 하고, 코덱이 같아야 하고, 요청한 챕터 수가 정확히 들어 있어야 해요. 확인에 실패하면 원본이 그대로 남아요.
- 작업이 중간에 멈추면 이미 다시 쓴 파일은 그대로 남아요. 오류에 "N of M files already updated"라고 나와요. 원인을 고친 뒤 Update를 다시 돌리세요.
- 처음부터 거부되는 경우: 그 책의 다른 변환이 돌고 있을 때, ASIN이나 Libex 챕터가 없을 때, 판본이 다를 때, 읽을 수 없는 파일이 있을 때, 업데이트할 게 없을 때.

## .cue 만들기

Libex 챕터로 cue 시트를 만들어 책 폴더에 써요. 이름은 첫 번째 오디오 파일을 따라요. 같은 이름의 기존 파일은 덮어써요. [사이드카 파일](/ko/using/sidecars/)을 보세요.

## 주의할 점

- 길이 헤더가 없는 VBR MP3 파일은 길이를 추정해요. 맞는 판본인데도 몇 초 차이 나 보일 수 있어요.
- 다시 쓴 파일은 Audiobookshelf가 바뀐 걸로 보고 다시 스캔해요.
- 챕터 제목에 `=`, `;`, `#`, 백슬래시가 들어 있으면 수정이 나올 때까지 잘못 써질 수 있어요.

## 변환 시 기본 챕터 동작

위 내용과는 별개로, 변환이 챕터를 어떻게 다룰지는 **Settings > Conversions > Chapter Handling**에서 정해요. [변환 설정](/ko/settings/conversions/)을 보세요.
