База даних це файл SQLite у `/config`, тож налаштовувати окремий сервіс бази даних не потрібно.

**Тобі знадобляться:**

- Docker із Compose
- Тека для твоєї бібліотеки аудіокниг
- Тека, у яку твій клієнт завантаження кладе готові завантаження
- Тека для власних даних ABM

## Встановлення

<Steps>

1. **Створи compose-файл.** Збережи це як `docker-compose.yml`:

   ```yaml
   services:
     audiobook-manager:
       image: ghcr.io/sunbrolynk/audiobook-manager:latest
       container_name: audiobook-manager
       restart: unless-stopped
       ports:
         - "${PORT:-5173}:5173"
       environment:
         TIMEZONE: ${TIMEZONE:-UTC}
         LOCAL_NETWORKS: ${LOCAL_NETWORKS:-}
         TRUSTED_PROXIES: ${TRUSTED_PROXIES:-}
       volumes:
         - /path/to/library:/audiobooks
         - /path/to/downloads:/downloads
         - /path/to/config:/config
   ```

2. **Вкажи свої теки.** Заміни ліву частину кожного тому на справжню теку на твоїй машині. Праву частину не чіпай.

   | Шлях на хості | Шлях у контейнері | Що там зберігається |
   |---|---|---|
   | `/path/to/library` | `/audiobooks` | Твоя бібліотека аудіокниг. Обов'язково. |
   | `/path/to/downloads` | `/downloads` | Куди твій клієнт завантаження кладе готові завантаження. Обов'язково. |
   | `/path/to/config` | `/config` | База даних SQLite, резервні копії, журнали, кошики та згенерований секрет застосунку. Зберігай її. |

3. **Запусти.** Виконай це в теці з compose-файлом:

   ```bash
   docker compose up -d
   ```

4. **Відкрий.** Перейди на `http://your-server:5173`. Під час першого візиту тебе проведуть через створення логіна.

</Steps>

<Aside type="tip" title="Завантаження в іншому контейнері?">
Якщо твій клієнт завантаження працює у власному контейнері, його тека завантажень має бути тією самою текою, яку ABM бачить як `/downloads`. Якщо шляхи різняться, додай віддалене зіставлення шляхів у **Settings > Download Clients**.
</Aside>

## Перший запуск

Задай часовий пояс через `TIMEZONE` у compose-файлі. Потім у **Settings** додай кореневу теку в **Media Management**, індексатор в **Indexers** і клієнт завантаження в **Download Clients**. Змінні середовища та зворотні проксі описано в розділі [Конфігурація](/uk/configuration/).

## Збірка з джерельного коду

Щоб зібрати образ самостійно, клонуй репозиторій, заміни рядок `image:` на `build: .` і виконай:

```bash
docker compose up -d --build
```

## Оновлення

Завантаж новий образ і перествори контейнер. На сторінці [Оновлення](/uk/updates/) перелічено, що змінилося в кожному релізі.

<Aside type="caution" title="ABM в альфа-версії">
Перед оновленням зроби копію `/config` і перегляни примітки до оновлення.
</Aside>

## Щось не так?

- **Сторінка не завантажується.** Перевір відображення портів у compose-файлі, потім виконай `docker logs audiobook-manager`.
- **Зміни відхиляються з мого домену.** ABM відхиляє зміни з адреси, за якою до нього не звертаються. Спершу налаштуй проксі так, щоб він передавав оригінальний заголовок `Host`. Якщо цього замало, додай свій домен до **CORS Allowed Domains** у **Settings > General** (це розширене налаштування, тож увімкни **Show Advanced**) і перезапусти ABM. Див. [Усунення несправностей](/uk/troubleshooting/).
- **Завантаження завершуються, але не імпортуються.** Перевір зіставлення тек у пораді вище.
