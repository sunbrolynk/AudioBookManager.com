ABM має REST API за адресою `/api`. Інтерактивний довідник лежить на `/api/docs` (Swagger) та `/api/redoc`, а схема на `/api/openapi.json`. Щоб прибрати всі три, задай `DOCS_ENABLED=false`. Сторінки документації завантажують ресурси з CDN, тож повністю відображаються лише з доступом до інтернету.

## Автентифікація

- **Ключ API**: надсилай `X-Api-Key: <key>` або `?apikey=<key>`. Знайти чи перегенерувати його можна в **Settings > General > Security**. Дивись [Безпека](/uk/settings/security/).
- **Bearer-токен**, отриманий після входу.
- Облікові дані, які ти передаєш, мають пріоритет над обходом автентифікації, тож запит із ключем із локальної мережі вважається запитом до API.

## Домовленості

- Помилки повертаються як `{"detail": ...}`.
- Секрети ніколи не повертаються. Відповідь лише каже, чи секрет задано.
- Запит із браузера, що змінює стан, мусить мати відповідне походження (origin). Скрипти з ключем від цього звільнені.
- Тіло запиту обмежене 10 MiB (`MAX_REQUEST_BODY_BYTES`). Відновлення з резервної копії та завантаження обкладинки мають більші ліміти. Понад ліміт буде HTTP 413.
- Помилки валідації ніколи не повертають назад те, що ти надіслав.
- `POST /api/tasks` ставить у чергу лише `backup_export`. Будь-який інший тип завдання отримує HTTP 403, а налаштування, які не підходять для `backup_export`, отримують HTTP 422. Ручний імпорт іде через ендпоінти `/api/manual-import/`, а сканування бібліотеки через `POST /api/library/scan`.
- `POST /api/manual-import/execute` і `/execute-to-book` перевіряють кожен рядок файлу за фіксованою схемою. Невідомий ключ, відносний `source_path` або порожній список `files` відхиляються з HTTP 422. Кожне джерело має бути аудіофайлом, який не лежить у системній теці, безпосередньо в теці верхнього рівня на кшталт `/tmp` чи `/mnt` або в одній із власних тек ABM (конфігурація, база даних, резервні копії, журнали, обкладинки, кошик, тимчасова тека й теки з SSL-сертифікатом і ключем), з переходом за символьними посиланнями. Відхилений файл отримує HTTP 400 зі своїм шляхом (`Can't import <path>: the file <reason>.`), і нічого не ставиться в чергу.
- `POST /api/manual-import/execute` і `/execute-to-book` дають кожному файлу назву за [Book Naming](/uk/settings/media-management/#book-naming) під час виконання імпорту й ігнорують `destination_filename` у рядку файлу.
- `POST /api/manual-import/check-conflicts` приймає `book_id` і `source_paths`, які ти хочеш імпортувати, і повертає в `destination_filenames` назву, яку отримає кожен файл, за шляхом джерела. `clashed` перелічує вихідні файли, які отримують назву з формату, бо їхня власна назва збіглася б з іншою. `audio_conflicts` і `other_conflicts` перелічують назви, які вже є в теці книги, без урахування регістру.

## Коли метадані недоступні

Запит, якому потрібне джерело метаданих і який не отримав відповіді, завершується помилкою з `detail`, що називає джерело та причину, ніколи не порожнім результатом. Пошук, на який ти чекаєш, здається приблизно за 10 секунд, коли Libex обмежує швидкість.

Якщо ти знаєш Sonarr: API не сумісний із v3. Prowlarr може синхронізувати індексатори в ABM через своє з'єднання Prowlarr.
