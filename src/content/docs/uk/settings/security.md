Розділ **Security** у **Settings > General** керує тим, хто може користуватися ABM і як.

## Автентифікація

| Налаштування | Типово | Варіанти |
|---|---|---|
| Authentication | Forms (Login Page) | None, Basic (Browser Popup), Forms (Login Page), External (Reverse Proxy) |
| Authentication Required | Disabled for Local Addresses | Enabled (Always), Disabled for Local Addresses, Disabled (Not Recommended) |
| Username, New Password, Confirm New Password | | Залиш пароль порожнім, щоб зберегти поточний |
| Certificate Validation | Enabled | Enabled, Disabled for Local Addresses, Disabled (Not Recommended) |
| Local Networks | порожньо | Додаткові діапазони CIDR, клієнтам яких не потрібно входити |
| CORS Allowed Domains | порожньо | Інші origin, яким дозволено викликати API з браузера. Потребує перезапуску |

Два режими **Authentication Required**, якими ти користуватимешся:

- **Enabled**: входять усі, зокрема твоя LAN.
- **Disabled for Local Addresses** (зберігається як `local_disabled`): запит з локальної адреси не потребує входу. Loopback, приватні діапазони, link-local та унікальні локальні IPv6 вважаються локальними. **Local Networks** додає інші й ніколи їх не замінює.

На свіжому встановленні запити відхиляються, доки не завершено налаштування.

## Зворотні проксі

За проксі задай `TRUSTED_PROXIES`, щоб ABM знав, яким заголовкам пересилання вірити. Запит із заголовками пересилання від адреси, якої немає в цьому списку, ніколи не є локальним і мусить увійти. Це зроблено навмисно. Див. [Зворотний проксі](/uk/guides/reverse-proxy/).

Проксі, який не надсилає заголовків пересилання, виглядає як локальний клієнт. Якщо ти таким користуєшся, встанови для Authentication Required значення Enabled.

## Підтвердження паролем

Деякі зміни знову запитують твій поточний пароль: збереження налаштувань Security, показ чи перегенерація ключа API, збереження або видалення конфігурації WireGuard. Неправильний пароль записується в журнал безпеки як невдалий вхід. Якщо пароль ще не задано, його не запитують.

## Ключ API

Ключ не показується, доки ти не підтвердиш пароль. **Regenerate API Key** створює новий, показує його один раз і негайно анулює старий. Ключ не можна ввести вручну. Якщо збережений ключ не вдається розшифрувати (змінився секрет застосунку), перегенеруй його.

Надсилай його як `X-Api-Key` або параметр `apikey`. Ключ з адреси LAN вважається запитом із ключем. Див. [API](/uk/system/api/).

## Записи з браузера

Браузерний запит, що щось змінює, відхиляється з `cross_origin_rejected`, якщо його origin не збігається з адресою, за якою відкрито ABM, пересланим хостом довіреного проксі або дозволеним доменом CORS. Запити з ключем API це не стосується.

## Політика безпеки вмісту

ABM надсилає заголовок Content-Security-Policy, якщо не задано `SECURITY_HEADERS_CSP_ENABLED=false`. Він обмежує UI власними скриптами й API ABM, а зображення дозволяє лише з ABM або через HTTPS. Обкладинки, що віддаються через звичайний HTTP, блокуються, а ABM у будь-якому разі не можна показати в iframe. Сторінки документації API отримують м'якшу політику, щоб завантажуватися з CDN.

## Невдалі входи

Блокування немає. Невдалі спроби записуються в журнал, групуються за адресою в Activity Log і построково записуються в журнал безпеки для інструментів на зразок fail2ban.

## Секрети

Паролі та ключі, які ABM зберігає для індексаторів, клієнтів і підключень, шифруються секретом застосунку. Задай `APP_SECRET`, щоб ключ не лежав на диску конфігурації. Якщо немає жодного, ABM генерує `/config/app_secret`. Паролі проксі та цілей експорту зберігаються відкритим текстом.
