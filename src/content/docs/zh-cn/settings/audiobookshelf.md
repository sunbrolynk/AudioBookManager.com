---
title: Audiobookshelf 连接
description: 把 ABM 连接到你的 Audiobookshelf 服务器。
---

Audiobookshelf（ABS）是你用来听书的服务器。在 **Settings > Audiobookshelf** 里把 ABM 连上去，电脑和手机上都能用。你要填服务器地址，以及为某个 ABS 用户创建的 API 密钥。

## 连接

- **Enable:** 让 ABM 使用这台服务器。开着它保存时，ABM 会先检查服务器，如果有错误级别的检查没通过，就拒绝保存，页面会告诉你原因。关着保存的连接不会被检查。
- **Server address:** 你的 ABS 服务器响应的地址，比如 `http://192.168.1.20:13378`。如果 ABS 和 ABM 跑在同一台机器上，就用这台机器的局域网地址；如果两者都在 Docker 里，就用容器名或 IP。
- **API key:** ABS 里 admin 用户的 API 密钥。
- **Verify TLS certificate:** 默认开启。如果你的服务器用的是你自己的证书颁发机构签发的证书，就在 **CA bundle path** 里填它的 CA 包路径，不要关掉验证。路径留空就用系统的证书。
- **Test:** 用屏幕上现有的内容跑检查，不保存任何东西。
- **Disconnect:** 先让你确认，然后删除已保存的地址和密钥。

## ABM 如何连到 ABS

ABM 总是直接连 ABS，从不经过你在 [Network](/settings/network/) 里选的 VPN 或代理。地址在保存前会被检查，不安全的会被拒绝。指回 ABM 所在机器自身的地址、链路本地地址和云元数据地址会被拒绝，解析到这些地址的名称也一样。你自己的局域网地址没问题，所以同一台机器上的 ABS 需要用这台机器的局域网地址，或者它的容器名或 IP。

## API 密钥

密钥加密保存，之后不会再显示。保存或测试时留空，就保留已保存的密钥。已保存的密钥只会发到保存时对应的地址，所以如果你改了地址、Verify TLS 或 CA 包，要重新输入密钥。如果 ABM 再也读不了已保存的密钥（加密密钥丢了或变了），即使连接是关着的，页面也会让你重新输入。

## 检查什么

**版本。** ABM 需要 ABS 2.37.0 或更新，并在 2.37.2 上测试过。更旧的服务器，或者没报出 ABM 能识别的版本的服务器，会报错。更新的会给出警告，因为 ABM 没在上面测试过。

**账户。** API 密钥属于某个 ABS 用户，ABM 会检查这个用户。

- **报错，直到修好：** 用户必须是 admin 或 root，并且有 Update 权限，以及对所有库、所有标签和成人内容的访问权限。
- **警告，照样保存：** Upload 关着（ABM 没法管理封面），或者 Delete 关着（你在 ABM 里删掉的书会留在 ABS 里，直到你打开它）。

## 状态

Status 部分显示上次检查的结果（Not connected、OK、Warning 或 Error）、服务器版本、密钥所属的用户、ABM 上次检查的时间，以及各项检查。没通过的检查会显示原因，通过的只计数。

连接开着时，[System > Status](/system/status/) 里也有一行 Audiobookshelf。它在你保存时刷新，也由每 6 小时运行一次的定期健康检查刷新，所以不是每次打开页面都实时探测。ABM 再也读不了的已保存密钥会显示为错误，直到你重新输入。还没检查过的连接显示为警告。关着的连接在那里保持安静。

## ABM 会删掉什么

ABM 在 ABS 里只会删掉条目记录，从不永久删除文件。
