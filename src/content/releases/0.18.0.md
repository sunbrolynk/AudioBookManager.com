### Upgrade notes

Read these before you update. Each one is described in full under Added, Changed, Fixed, Removed or Security below.

**Before you upgrade**

- **Back up first, and know the way back.** A migration rewrites the custom cover URLs stored on your books. To go back to 0.17.0, run `alembic downgrade b8d41e6f2a93` from a container still running this image, then switch the tag.
- **Reverse proxy:** also pass `/initialize.json`, `/media-cover/`, `/backup/` and `/logfile` to ABM, and let the WebSocket subprotocol header (`Sec-WebSocket-Protocol`) through, or the web interface can't get its key and live updates fail.
- **Proxy that rewrites `Host`** (nginx's default `proxy_pass` does): set `proxy_set_header Host $host;`, or add ABM's public address to CORS Allowed Domains in Settings > General > Security and restart ABM, so live updates connect. This was already needed in 0.17.0.

**After you upgrade**

- **Reload any open ABM tabs.** Pages opened before the update get 401s until you do.
- **Sign-in page (Forms) with Authentication Required set to Enabled:** you stay signed in and the web interface fetches the key itself. Anything calling `/api` with your login token (`Authorization: Bearer`) now gets 401; send the API key instead.
- **Forms or Basic with Authentication Required set to Disabled for Local Addresses:** the web interface still opens from your network without signing in. Scripts and tools on your network that called `/api` without a key now get 401, so give them the key. Anyone who can open ABM from your network can read the API key in Settings.
- **Basic:** the browser prompt works as before. A script that sends Basic credentials to `/api` gets 401; send the key instead.
- **Authentication None, or Authentication Required set to Disabled:** the web interface opens as before, and tools must send the key.
- **Prowlarr and anything already sending the API key** keep working.
- **Calendar:** copy the subscribe URL again from the Calendar page. The new one carries your key.
- **New installs** preselect "Everywhere" for sign-in in first-run setup. Existing installs keep their setting.
- **If the stored API key can't be decrypted** (`APP_SECRET` or the host changed), ABM makes a new key at startup and keeps the old one. Put the new key into Prowlarr. If the right `APP_SECRET` comes back, the original key returns and the interim one stops working.

### Changed

- **The calendar feed dialog waits for the API key** before showing the URL, and warns that regenerating the key breaks subscribed calendars until the URL is copied again.
- **If live updates can't reconnect, the page now says so** instead of going quiet.

- **Covers, backup downloads and log downloads moved out of `/api`.** `/api/media-cover/...` is now `/media-cover/...`, a book's custom cover `/api/books/{id}/cover` is now `/media-cover/custom/{id}`, the import cover preview is now `/media-cover/import/{session}`, `/api/settings/general/backup/download/{file}` is now `/backup/{file}` and `/api/logs/download` is now `/logfile`. They open with your sign-in or with the API key.
- **The calendar subscribe URL now includes the API key.**
- **Regenerating the API key disconnects open pages,** which reconnect with the new key.
- **The live-update connection (`/api/websocket`) needs the API key** like every other API call.
- **`/initialize.json` and the live-update connection refuse other sites' pages.** A request your browser marks as coming from another site, or one carrying another site's `Origin`, is refused. Scripts that send no `Origin` aren't affected.
- **Reverse proxies must pass more paths.** Along with `/api` and `/`, pass `/initialize.json`, `/media-cover/`, `/backup/` and `/logfile` to ABM, and let the `Sec-WebSocket-Protocol` header through.
- **`/api/auth/status` reports whether the web interface is open to you,** from your sign-in or the local-address setting. It no longer looks at an API key.
- **An API key that can no longer be decrypted is replaced automatically** at startup. If the old key becomes readable again, for example after `APP_SECRET` is put back, the original key comes back on the next start.

### Fixed

- **An API key with non-ASCII characters gets a 401 instead of a server error.**
- **Rejected API keys are logged with the caller's address,** so fail2ban can act on them.
- **The calendar subscribe URL works from outside your network.**

### Removed

- **Login tokens no longer work on the API.** An `Authorization: Bearer` token from signing in is refused, and login, setup and saving the security settings no longer return `access_token` or `token_type`. The sign-in cookie is unchanged. `/api/auth/check`, `/api/auth/validate-token` and `/api/auth/validate-api-key` are removed. Use `GET /api/system/status` with your key to test it.
- **The password prompt to show the API key is gone,** along with `POST /api/settings/general/security/api-key/reveal`. The key shows on the Security settings page. Regenerating it still asks for your password.

### Security

- **Every API call needs the API key.** The key is required even from your own network and even when signed in, the way Sonarr and Radarr work. Signing in, or the local-address bypass, opens the web interface, which then uses the key itself.
- **`.box` hostnames no longer count as local addresses.** `.box` is a public top-level domain, so a site on it could have passed the local-address check.
- **Signing in and first-run setup refuse requests from other sites.** When your browser marks a login or setup request as coming from another site, it gets a 403, so a page elsewhere can't sign your browser into a different account. Browsers only mark requests to `https` and `localhost` addresses, and scripts send no mark, so those keep working as before.
