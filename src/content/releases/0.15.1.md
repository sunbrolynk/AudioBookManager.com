### Fixed

- the `metadata.json` ownership marker `0.15.0` shipped as a separate
  hidden `.abm.json` file inverted the behavior that marker was supposed to
  produce. Audiobookshelf never reads or writes `.abm.json`, so ABM
  believed it owned `metadata.json` forever regardless of what happened to
  it — meaning an edit made directly inside Audiobookshelf would be
  silently reverted the next time ABM touched the book, exactly backwards
  from the `0.15.0` entry below's claim that editing in Audiobookshelf was
  how you'd opt a book out. The marker is now an `"abm"` block written
  inside `metadata.json` itself. Audiobookshelf ignores that block on read
  and always discards it on its own rewrite, so editing a book's metadata
  in Audiobookshelf is now what tells ABM to back off: ABM sees a
  `metadata.json` with no block and leaves it alone from then on. Deleting
  the block by hand does the same thing. `.abm.json` is no longer read or
  written at all.

  **If ABM wrote a book's `metadata.json` while `0.15.0` was running:**
  that file has no `"abm"` block, so as of this release ABM treats it as
  foreign and will not touch it again on its own. If you want ABM to keep
  managing that book, delete its `metadata.json` (and the now-unused
  `.abm.json` beside it, if present) — the next import or refresh
  regenerates it correctly. If you're fine with what `0.15.0` wrote and
  don't want it changed, no action is needed; that's now the same outcome
  as having edited it in Audiobookshelf.
