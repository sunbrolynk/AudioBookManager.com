### Fixed

- writing a tag or embedding cover art into a book file that's still
  hardlinked to a seeding torrent edited the seeding copy in place — ABM and
  the torrent client shared the same inode, since hardlinking is the default
  behavior when `useHardlinks` is on, and mutagen writes to a hardlinked file
  in place. The first tag write or cover embed after import could break that
  torrent's hash check. ABM now checks for a shared link before writing and,
  if one exists, copies the file to a private one in the same directory
  first, so the seeding copy is never touched. **This only protects writes
  going forward.** If you've been running with hardlinks on, any torrent
  whose book got tagged or had a cover embedded after import may already
  have a broken hash — check your client for anything that's stopped
  seeding or failed its recheck, and re-add it if so.
- adding chapters to a book in place could damage a seeding torrent the same
  way, by a different route. The chaptered file was written to the system temp
  directory and then moved onto the library file — and when those sit on
  different filesystems, as they do in any normal Docker setup, that move
  becomes a copy that rewrites the existing file's contents rather than
  replacing it, so the seeding copy's bytes changed underneath it. The
  chaptered file is now written alongside the book and swapped in by renaming,
  so the seeding copy keeps exactly the bytes it was hashed against. The same
  caveat applies — this protects writes going forward, not ones already made.
- creating `cover.jpg` for a book with a custom cover failed with "Cover URL
  rejected: URL scheme '' not allowed". A custom cover is stored inside ABM and
  referenced by an internal path rather than a web address, so the download
  step rejected it. It now copies the stored custom cover into the book folder
  instead — which matters when the folder's `cover.jpg` has been deleted or the
  book has been reorganised, since that button is how you'd put it back.
- a book's `.opf` metadata file came out with malformed XML if its title,
  author, narrator, publisher, ASIN, genre, language, or series name
  contained `&`, `<`, or `>` — only the description was ever escaped.
  Audiobookshelf discards a `.opf` it can't parse, silently, so any affected
  book's OPF was never actually read. Every field is escaped now, and the
  series name and position are quoted properly. **If you've generated an
  OPF for a book whose metadata contains one of those characters:**
  regenerate it — this fix doesn't rewrite files already on disk.
- `reader.txt` listed narrators one per line, but Audiobookshelf only reads
  the file's first line — every narrator after the first was silently
  dropped for any multi-narrator book. Narrators are now joined the way
  Audiobookshelf's own parser expects, so all of them show up.
- a book's `.opf` listed narrators under `<dc:contributor opf:role="nrt">`,
  which matches the OPF spec but not what Audiobookshelf reads — its parser
  only looks at `dc:creator`. Every narrator ABM has ever written to an OPF
  file was invisible to Audiobookshelf. Narrators are now written as
  `dc:creator opf:role="nrt"`, the same element authors use.
- author and narrator names written to tags, `reader.txt`, and `.opf` files
  were joined with `; `. Audiobookshelf splits those fields on its own
  precedence — `&` first, then `and`, then `;` — so a name that itself
  contains one of those characters (an author credited as "Anne & Todd
  McCaffrey", for example) got split apart instead of read as one name.
  Names are now joined with `&` with those characters stripped from each
  individual name first, so Audiobookshelf's `&` split always wins and never
  fires in the wrong place.

  **None of the four metadata fixes above rewrite what's already on disk.** They only
  change what ABM writes from now on. If you want an existing book's tags,
  `reader.txt`, or `.opf` corrected, re-tag it or use the "Create reader.txt"
  / "Create .opf" actions to regenerate them.

### Changed

- all four `/api/metadata` endpoints that create files — `cover.jpg`,
  `reader.txt`, `desc.txt` and `.opf` — now reuse the same code library import
  and refresh already use, instead of second copies that carried the same
  metadata bugs independently. One visible
  side effect: creating an OPF for a book with no audio file on record now
  falls back to `title.opf` instead of `<Book Title>.opf`. Nothing in ABM
  reads that fallback name back, so this only matters if you were relying
  on the old filename yourself.
