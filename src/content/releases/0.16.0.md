### Changed

- **empty book folders are now created only if you ask for them**, matching how
  Sonarr works. Settings > Media Management > **Create Empty Book Folders**,
  off by default. It covers all three places a folder gets made: adding a book,
  changing its root folder, and a disk scan. As in Sonarr, turning on "delete
  empty folders" suppresses it — creating a folder something else is set to
  sweep away only churns it.

  **If you had previously saved the Media Management page, your existing
  behaviour is preserved and the new setting comes up on.** A fresh install, or
  one that never saved that page, will have it off.

### Fixed

- a file's folder and its name are stored in separate places, and one importer
  was writing the whole file path into the folder column. Anything that later
  looked for that file built a path that could not exist, so a refresh treated
  it as missing and dropped the record. Fixed, and a repair pass runs once at
  startup to correct any record already written that way — it reports what it
  changed on the Tasks page and does nothing at all when there is nothing wrong.

- re-importing the same download created a second, duplicate record of every
  file, because the check for "do I already have this?" compared a full file
  path against a column holding folders and so never matched.

- an upgrade whose new file landed at exactly the same path as the one it
  replaced could leave the book with no file records at all, and could keep
  re-running the same upgrade indefinitely because the record still described
  the old file's audio.

- moving a book kept its files' sub-folders (`Disc 1`, `CD2`) in one place and
  flattened them in three others, so after some moves those files could no
  longer be found. All four now behave the same way.

- if a move succeeded on disk but the database write that followed it failed,
  the folder stayed at its new location while ABM still pointed at the old one.
  The folder is now put back.

- bulk edits that move books now save each book as it goes, so one failure part
  way through no longer leaves every folder already moved unaccounted for.

- the root folder removal dialog described two things that do not happen: that
  removing a folder leaves everything else untouched, and that deleting its
  files also deletes the books. It now says what actually happens, and the book
  count it shows is correct — a root folder whose name began with another one's
  name was counting the other folder's books as its own.

- a scan skipped reconciling any book whose folder was missing, so a book whose
  files had gone was never noticed.

- a converted book kept reporting the quality it had before conversion. The
  conversion refreshed the file's format but left the audio properties read from
  the original, and the quality classifier trusts those over the extension — so
  an upgraded-by-conversion book could look like it still needed upgrading.

- a background task that failed while saving recorded its own failure against a
  session that first needed resetting, so the failure could go unrecorded.

- the startup file-path repair was registered as safe to retry after a database
  lock but could never actually retry, because it reported the lock as a result
  rather than raising it.
