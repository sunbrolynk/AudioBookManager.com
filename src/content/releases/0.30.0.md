### Upgrade notes

Read these before you update. Each one is described in full under Added, Changed, Fixed, Removed or Security below.

- **Check your recycle bin folder if deletes with files start failing.** While the recycle bin is on, deleting books, authors, series or a root folder with their files is now refused, with the reason, until the bin folder exists and ABM can write to it. Fix or clear the path in Settings > Media Management.
- **Deleting a root folder with its files no longer empties the root.** Anything scripted against `DELETE /api/settings/root-folders/{id}?delete_files=true` should expect only its books' folders to go, through the recycle bin when it's on. The root folder and anything else in it stay, and the call is refused for a root folder that isn't an existing directory.
- **Empty folders outside your books stay after a scan.** With Delete empty folders on, a scan only removes empty folders left by a book, so empty folders an earlier version would have cleared, such as a share's mount point, are now left for you to tidy.

### Changed

- **Delete empty folders only clears your books' folders.** With Delete empty folders on, a library scan used to remove every empty folder in a root folder, down to three levels, whether or not a book had ever been there. It now works the way the arr apps do, one book at a time. A book's folder with no files left is removed, along with the author and series folders that leaves empty, up to but never including the root folder. A book's folder that still has files only loses its empty subfolders. An empty folder no book records, such as an unmounted share's mount point, is left alone, and so is a book folder that holds another book's folder, a root folder, the recycle bin or ABM's own data.

- **Fewer folders are off limits.** ABM now refuses only the folders the arr apps refuse (`/bin`, `/boot`, `/lib`, `/sbin`, `/proc`, `/usr/bin` and anything inside them), ABM's own data folder and the recycle bin. A library at `/mnt`, `/media`, `/srv`, `/opt`, under `/run/media` or anywhere else is fine, and so is a root folder, recycle bin, scan folder or manual import from there. A refusal names the path in the arr apps' words, such as "Path '/boot/books' is child of system folder /boot". A path is judged both as written and where its links lead. A root folder at `/` holds every path, so it can't sit alongside another root folder or hold the recycle bin. New folder in the folder browser still won't create a folder directly in `/`.

- **Deleting a root folder with its files never deletes the root folder itself.** It used to delete everything under the root folder. Now each book recorded under it is deleted the way deleting that book deletes it, through the recycle bin when it's on, and its emptied author and series folders are tidied away. The root folder itself and anything in it that isn't a book's folder stay on disk. A root folder that isn't an existing directory, such as an unmounted share, is refused rather than having its books' rows removed while their files are unreachable, and so is a delete while the recycle bin is on but its folder doesn't exist, can't be written to or doesn't answer. When some files can't be deleted, a warning says how many, in how many books.

### Fixed

- **Removing a blackhole download never deletes outside its own entry.** Only an entry directly in the watch folder is removed, never a path inside one or an entry that links somewhere else. A watch folder at the top of the filesystem has nothing removed from it, and an entry that is, or holds, a root folder, the recycle bin or ABM's own data is never deleted.

- **Deleting a book, or removing a Library Import row, never takes a folder that holds something else you need.** Deleting a book with its files no longer deletes its whole folder when that folder is, or holds, another book's folder, a root folder, the recycle bin or one of ABM's own folders. Only the book's own files go, and the folder stays. Removing a Library Import row is refused, with the folder named, when the row is or holds a root folder, the recycle bin or one of ABM's own folders. A row must also sit inside the folder that was scanned, and must not overlap a book in your library.

- **Deleting a book with its files never deletes through a link.** When the book's folder is a link, only the book's own files go, and the folder the link leads to keeps everything else in it. A folder that another book is recorded in by its real path, past a linked parent folder, is never deleted whole either.

- **A delete with files is refused while the recycle bin can't take them.** When the recycle bin is on but its folder doesn't exist, can't be written to or doesn't answer within a few seconds, deleting books, authors, series or a root folder with their files stops with the reason before anything changes, instead of removing them from ABM and leaving their files behind. A missing bin folder is never created by a delete, since it may be a share that isn't mounted.

- **FTP and FTPS backup exports name the folder when they're refused.** A folder the server won't let ABM open, create or write to is named in the message, and so is a folder that can't be created for any other reason, instead of a bare "The server refused the request." A server that replies it is out of space or over its quota now says so.

- **Library Import checks where a book is going, not only where it comes from.** The root folder a book is imported into is checked when the import runs instead of being trusted from when it was queued, once per root for the whole import, and a slow or sleeping network share is waited for up to two minutes. A root that is missing, can't be read or doesn't answer fails its rows with "Root folder does not exist", "Root folder cannot be read" or "Root folder is not answering" and is never created, so an unmounted share no longer fills up the local disk, and a root or author folder that now leads into a system folder fails the row before anything is placed. Adding files to a book already in the library is checked the same way. Rows answered "keep the library copy" or "remove empty folder" are now checked like imported rows before anything is removed, and so is a single file sitting directly in a system folder. Restoring a kept conversion original now checks where it goes: a restore whose folder leads into a system folder, or whose root folder is missing, unreadable or not answering, is refused before anything is moved. A conversions recycle folder that is a link to an ordinary folder, such as one on another disk, still works; one that leads into a system or app data folder is refused. A conversion original left in a previous recycle bin folder after the bin was moved can now be purged as well as restored.

- **A Library Import scan leaves out a folder whose files lead into a system folder, and the import refuses one, so nothing is placed from there.** The scan says how many folders it left out, in the scan result and the operation log. A book whose files link to another ordinary folder is still offered and imports.

- **Background jobs no longer trust a folder that has since become a link to a system folder.** A library scan used to walk a root folder, and remove empty folders under it, even after that root had been replaced by a link to a system folder, and its empty-folder cleanup followed links inside the library to folders outside it. A root like that is now refused with one error on the scan task while the other roots still scan, its books are left alone by every scan (no folder is created for them), and the cleanup never follows a link or leaves the root. The same check runs when a Library Import row is imported and when a book is refreshed, and a recycle bin that now leads to a system folder or the app's own data folder is no longer aged. When the conversion recycle bin can't be used, the Recycle Bin Cleanup task says why it left expired conversion originals in place. A library root that is itself a link to an ordinary folder, such as one on another disk, scans and imports as before.

- **An interrupted SFTP, FTP or FTPS backup export no longer leaves a cut-off backup behind.** The backup uploads under a temporary name and only takes its real name once the upload finishes, replacing any backup with the same name. A failed upload removes the temporary file, unless the old backup was already removed, in which case the finished temporary file is kept so a copy is left on the server.

- **A library root that stops answering is now caught before anything touches it.** A scan used to check a root, list its book folders and run its empty-folder and recycle bin cleanup before asking whether the root was answering, so a stalled network mount could hang the scan. The root is now asked first, with a time limit, and the scan says what it found: "Library root does not exist", "Library root cannot be read (Permission denied)" for a root ABM has no permission on, or "Library root is not answering", while the other roots still scan. A book folder that leads into a system folder is no longer listed or read by a scan, a Library Import row is refused if any file it would place leads into one (a linked file pointing at another ordinary folder still imports), a row with no folder is reported as missing, and kept conversion originals are no longer deleted from a recycle bin that leads into a protected folder.

- **A library scan or book refresh no longer hangs on a library root that stops responding.** If a root folder was on a network share that stopped answering, a scan could stall on one of that root's books, and refreshing such a book could stall the same way. The root is now checked first, and a share that is slow to wake, such as a sleeping NAS, is waited for up to two minutes, once per root per run. A root that still doesn't answer has its books skipped as "its root folder is not answering" while the other roots carry on.

- **A library scan reports a root folder it couldn't scan, and a book error no longer fails it.** Each root folder that couldn't be scanned is listed once on the scan task with its reason (it does not exist, cannot be read, is not answering, or leads into a system folder), after every other root has been scanned. The scan then counts as failed and sends its failure notification, so an offline share is never hidden behind a scan that looks done. Errors on single books don't fail the scan; they're listed on a completed scan instead. A scan of chosen root folders only counts the roots it was asked to scan.

- **SFTP backup exports say what went wrong.** Testing a target on a host that can't be reached now says it couldn't connect, instead of pointing you at the log. A folder the server won't let ABM read, create or write to is named in the message, and so is a folder that can't be created for any other reason.
