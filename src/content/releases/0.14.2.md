### Fixed

- adding chapters to a file (Chapterize, and Convert's step that embeds
  fetched chapter data into a source that had none) wiped every embedded
  global tag — title, author, narrator, ASIN, description — from the
  output. The ffmpeg command mapped metadata only from the chapters file,
  which carries chapter markers and nothing else, so the container ended
  up with none either. Convert and Merge run through the same step, but
  had it masked: a database re-tag runs after them regardless, so the
  file got its tags back anyway. Chapterize has no such re-tag step, so
  the loss was permanent — chapterizing a book actually stripped it of
  its tags, not just risked it. Fixed by keeping the source's own global
  tags and layering the chapter markers on top instead of replacing
  everything. **If you've chapterized a book, or converted one that
  picked up chapters this way, before this fix:** its embedded tags are
  still gone and this fix won't bring them back — re-tag the file with an
  external tool or replace it from wherever it originally came from.
- the same metadata-wiping command ran on the Audible download decrypt
  path too, and nothing masked it there: `write_audio_tags` defaults to
  off for Audible downloads, so no re-tag step ever ran to put the title,
  author, and ASIN back. Every Audible book decrypted before this fix is
  missing those tags in the file itself. Same fix, same caveat: already-
  decrypted files won't recover on their own.
- adding chapters to a file in place could delete the very file it had
  just finished producing. The temp file ffmpeg wrote to and the final
  destination were tracked under the same variable once the move to its
  final location succeeded, so the cleanup step that's supposed to remove
  the temp file removed the finished file instead — silently, right after
  reporting success. This hit the same three operations as above:
  Chapterize (single file and multi-file), and Convert's post-conversion
  chapter-embed step.
