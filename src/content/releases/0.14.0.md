### Added

- the Audible Library page can now show Virtual Voice and Subscription Plans
  icons on its books, matching Library and Discover. It could already sort
  and filter by that data, but the options modal had no toggle to display
  it, so there was no way to see it even if you owned the titles. Both are
  off by default, the same as on Library and Discover.

### Changed

- Libex's metadata host is moving off `libex.lostcartographer.xyz` ahead of
  that host's retirement; ABM now points at `libexdb.com` by default. **If
  you had the `LIBEX_BASE_URL` environment variable set to override it:**
  that variable is gone and no longer has any effect — ABM always uses
  `libexdb.com` now.
- the "Release Date" column and toggle on Library, Series, and Audible
  Library only ever showed a year, never a full date. Relabeled to "Release
  Year" so the label matches what's actually shown.

### Fixed

- System > Status always showed the database as "PostgreSQL (connected)"
  under Database, no matter what was actually running or whether it could be
  reached — the row was never checked, just always displayed that way. It now
  opens the database and reports what's really there, e.g. "SQLite 3.45.1",
  and if the database can't be reached it says "unavailable" instead of
  claiming it's connected.
- interactive indexer search (the search dialog on the book detail page) no
  longer waits for indexers one at a time. Indexers within a tier are now
  queried at once instead of in sequence, so the wait is roughly the
  slowest indexer's response time rather than the sum of every enabled
  indexer's. A slow or failing indexer no longer holds up the rest —
  concurrency is capped at 5 at once, so a setup with several indexers
  behind the same proxy isn't hit with a bigger burst than that.
- "Add Series" could report success after adding only the first book. It
  created that book, then waited a fixed amount of time hoping the rest of
  the series had finished being set up before checking once — on a slower
  server, a large series, or a busy machine, that single check could land
  too early. When it did, the rest of the books were silently skipped, but
  the app still showed the add as successful and closed the dialog. It now
  keeps checking until the series is actually ready, for up to 10 seconds,
  before adding the rest.
- "Add Series" now tells you when it fails instead of closing the dialog
  regardless. The dialog stays open while the series is being added, and if
  something goes wrong — most commonly a slow catalog build that hadn't
  finished in time — it stays open with a message explaining what happened,
  and the buttons re-enable so you can just try again. When the failure
  happened after a log was already being written for the attempt, the
  message includes a "View Related Logs" link straight to it; if nothing had
  gotten far enough to produce a log, there's no link.
- the Virtual Voice and subscription-plan icons on Library, Discover, and
  Audible Library announced nothing to a screen reader — they were silently
  skipped over, so anyone relying on one had no way to know a book was
  AI-narrated or included with a subscription. They now announce as
  "AI-narrated (Audible Virtual Voice)" and "Included with Audible
  subscription plans: <plan names>". This has been broken since these icons
  were introduced, not just on the new Audible Library toggle above.
- Virtual Voice sorting and filtering on the Audible Library page could give
  the wrong answer for any book that was already in your library before that
  data started being tracked — it had been permanently recorded as
  AI-narrated whether or not it actually was, so filtering for
  non-Virtual-Voice titles could turn up nothing even though you own plenty.
  A normal library sync already corrects a book the next time it runs, but
  anything that hadn't been re-synced since was still wrong. This is
  repaired for every remaining case automatically as part of upgrading, so
  the new toggle above shows the right icon for everyone from the start.
- an Audible-library sync that fell back to the Audible API instead of
  Libex — which happens whenever Libex can't be reached — could silently
  blank out a book's series, genres, release date, rating, Virtual Voice
  status, subscription plans, and Audible ownership type. The fallback
  builder asserted a default for every field it had no data for, and a sync
  writes every field it builds, so a prior Libex sync's real values got
  overwritten with those defaults. This is now closed for every field on
  that path: the fallback builder leaves a field alone instead of guessing
  at it when it has nothing to say, and extracts series and release date
  from the Audible payload where that payload does carry them. If your
  library synced while Libex was unreachable before this fix, the affected
  books won't recover on their own — a normal sync refills them from Libex
  the next time it runs; trigger one manually if you don't want to wait for
  the schedule.
- a book's release date could show as a day earlier than it actually is.
  Upstream sends a release date as a full timestamp even though it carries
  no time of day, and stored that way it reads as a UTC instant — any
  client behind UTC renders the day before. This came in through more than
  one path: normal metadata syncing, adding a book manually with a release
  date supplied directly, and the Audible fallback used when Libex has no
  date for the ASIN. Release dates are now stored and validated as a plain
  calendar date everywhere they're written, with an invalid one rejected
  rather than stored, and any date already stored as a full timestamp is
  corrected automatically as part of upgrading.
- the library-import manual-search and preview API endpoints
  (`/api/library-import/search`, `/api/library-import/preview/{asin}`) handed
  the raw Libex response straight to the response formatter instead of
  parsing it first. A direct ASIN search or preview came back with no cover,
  no release date, and no runtime; every search — ASIN, title, author, or
  series alike — came back with no publication year and no subtitle, because
  the formatter was reading those two under names the parser has never used.
  Both are corrected. Neither endpoint has a caller anywhere in ABM today —
  not the frontend, not any background handler — so this is a fix to the
  public API contract those endpoints advertise, not something you'll see
  change on screen.
- the Audible Library page's release year could come out a year off for a
  book near a year boundary. Its release date was sent to the browser as a
  full UTC-tagged instant even though it's only ever a calendar date, so a
  browser behind UTC could compute the wrong year from it — the year shown
  on poster and overview cards, and sorting by year, were both affected.
  Year is now read off the bare calendar date instead.
- the Audible Library page showed a book as unmonitored, even when it
  wasn't, whenever it matched your library by ASIN rather than through its
  stored link — that code path resolved the match but never read the
  matched book's monitored flag. Fixed. Loading the page is also faster
  with a large Audible library: each book's library match is now looked up
  in one batched query instead of one query per book, and the page no
  longer writes to the database as a side effect of loading it.
- a saved filter created on the Library, Series, or Discover page showed up
  — and could be applied — on all three, because the three pages shared one
  stored-filters slot. Each page now keeps its own. **If you have saved
  filters:** they were stored under the old shared slot, which nothing
  reads anymore, so they won't appear after upgrading — recreate the ones
  you want to keep on each page.
