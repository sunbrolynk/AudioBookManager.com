### Fixed

- author and narrator names written to tags, `reader.txt`, and `.opf` files
  could still be split apart by Audiobookshelf after `0.14.3`'s fix for
  exactly that problem — `0.14.3` sanitized a name by replacing `&` with
  the literal word `" and "`, but `" and "` is Audiobookshelf's own second
  split, right behind `&`. With two or more names the join's own `&`
  still won and covered for it, but most books have only one name — with
  nothing to join, there was no `&` at all, so Audiobookshelf split on the
  `" and "` the sanitizer had just inserted. `Anne & Todd McCaffrey` came
  out of `0.14.3` as two authors, `Anne` and `Todd McCaffrey`. A name that
  legitimately contains the word "and" (`Crosby and Nash`) split the same
  way. Both are fixed the same way now: `&`, `,`, `;`, and the literal
  word `" and "` are all stripped out of a name before joining, so nothing
  Audiobookshelf treats as a separator is left inside a single name.
  **If a name in your library contains `&` or the word "and":** that text
  is now dropped from what ABM writes for it — `Anne & Todd McCaffrey` is
  written as `Anne Todd McCaffrey` — because leaving any of it in is what
  caused the split. This doesn't rewrite what's already on disk; re-tag a
  book or regenerate its `reader.txt` / `.opf` to pick up the corrected
  name.
- adding chapters to a book in place — Chapterize, and the in-place case of
  `0.14.3`'s hardlink-safety fix — staged its temp file next to the real
  file with a real audio extension and no protection against a same-named
  collision. A library scan or the file watcher could see the half-written,
  multi-gigabyte remux mid-write and treat it as a new audio file; and
  because the file's own name carried nothing more than a process ID, two
  chapter operations landing on same-extension files in the same folder at
  the same moment could stage to the identical path and race each other's
  swap onto the live file. Staging now uses a collision-proof name that
  scans and the file watcher never mistake for real content, with ffmpeg
  told the container explicitly since the staged name no longer carries a
  usable extension. The swap also now carries the original file's
  permissions across, which it didn't before — the staged file was created
  more restrictively than the original, so a completed chapter add could
  quietly leave a file only ABM's own user could read.
- the hardlink-safety fix in `0.14.3` (copying a file to a private inode
  before an in-place tag or cover write) could leave a permanent orphan
  file behind in the library folder if ABM was interrupted between staging
  the copy and swapping it in — its temp file had no suffix a cleanup pass
  could recognize, so nothing ever came back for it. It now stages through
  the same collision-proof, sweepable temp file as the chapter fix above,
  and a leftover from an earlier interruption is cleaned up automatically
  the next time the same operation runs on that folder.

  **If you already have a stray file from a crash before this fix:** the
  automatic sweep only recognizes the new naming pattern. Look for a dotfile
  next to a book's audio file that isn't `cover.jpg`, `reader.txt`, or
  `.opf` — for chapters, named like `.temp_chapters_<pid>_<time>.m4b` or
  `.chapters_temp_<pid>.m4b`; for a tag or cover write, named like
  `.<book file>.<random>` with no extension at all. Safe to delete by hand;
  nothing in ABM will pick it back up.
