### Upgrade notes

Read these before you update. Each one is described in full under Added, Changed, Fixed, Removed or Security below.

- **Back up first, and know the way back.** This release adds columns to your books and catalog tables, adds a WireGuard tunnel table, and rewrites stored book paths. If the image refuses to start after the update, do not just put the old image tag back: from a container still running the 0.20.0 image, run `alembic downgrade d7f3a91c2e58` and then `alembic upgrade c4e7a19d5b36`, then switch the tag back to 0.19.1. Both steps are needed because this release's migrations branch off at `d7f3a91c2e58`; `alembic downgrade c4e7a19d5b36` alone leaves the new branch recorded and 0.19.1 refuses to start with "Can't locate revision". Going back drops the new explicit, abridged, subtitle, Plus-catalogue plan, VVAB and released values and any WireGuard tunnels. The book-path cleanup cannot be undone, which is harmless: the paths point at the same folders. Passwords and feed URLs are encrypted on first start and an older ABM cannot read them, so after rolling back, re-enter the proxy password, the backup export passwords and the RSS feed URLs.

- **All of ABM's internet traffic is blocked until you choose a connection.** After updating, open Settings > Network and pick a proxy, a WireGuard tunnel or Direct (Direct needs an explicit acknowledgement). An enabled HTTP, HTTPS or SOCKS5 proxy you already had is carried over as your chosen connection, so it needs no new choice.

- **Scripts that call the old proxy or public-IP routes get a 404.** Move them to `GET`/`PUT /api/settings/network` and `POST /api/settings/network/proxy/test`; the public-IP check is now on the Network page.

- **Restoring a backup keeps your live network, proxy and security settings** unless you opt in to restoring them.

### Added

- **Every file Audiobookshelf reads is written on every import.** A finished download, an upgrade, a manual import and a finished conversion now write the same sidecars as a library import, including a new `<audio file name>.nfo`. The `.opf`, `.nfo` and `metadata.json` are built from one set of values so they no longer disagree. The `.opf` and `.nfo` leave out genres so a cleared genre stays cleared, no file carries a tag list, and a series sequence is always written without spaces (`1 - 3` becomes `1-3`). Books already in the library get no sidecars retroactively; they are written on the next import or refresh. Genres are in `metadata.json` only, so anything that read genres from the `.opf` should read them there.

- **A Network page under Settings.** One place for how ABM reaches the internet. Its sections run in the order you'd set them up: Proxy (HTTP, HTTPS, SOCKS5 or SOCKS5 with remote DNS), WireGuard (paste or drop your `.conf`, checked by the server before you save), Connection (which one ABM uses), Routing (which of ABM's traffic uses the connection, shown with Show Advanced) and Public IP. The Public IP check shows the address the world sees for ABM and when it was last checked, so you can see the connection is really in use, and the check on the Audible page uses the same name. It replaces the old public-IP rows on the General and Audible pages, and the proxy that used to sit under General now lives here.

- **The Docker image now includes wireproxy**, which runs the WireGuard tunnel without needing extra container privileges. It is built from a pinned release and the build fails if the source or the resulting binary doesn't match its recorded hash.

- **Explicit and abridged on every book.** Both come from the metadata source when a book is imported or refreshed, and show on the book's detail page and its phone view. The metadata.json written for Audiobookshelf carries a known value as true or false and leaves an unknown one out, so Audiobookshelf keeps its own, and it never writes tags, so tags set only in Audiobookshelf are left alone.

- **Audible accounts in Brazil.** You can add an account on the Brazilian Audible store (audible.com.br).

### Changed

- **A release `.nfo` is no longer imported unless you choose it, and deleting a book's files removes ABM's own `.nfo`.** Audiobookshelf reads one `.nfo` per book and ABM now writes its own, so the one that comes with a release is left behind by default.

- **Connected Audible accounts are laid out as one aligned table.** Each account shows its region, book count, last sync, date added and Enabled checkbox in its own column. An account that needs signing in again shows Re-authenticate where Sync now usually sits. On a phone each account gets its own card. The dark panels on this page use the same grey as the rest of the app instead of navy.

- **The book page's stats sit in one even row.** Rating, runtime, language, content and publisher share one line with a divider between each, instead of wrapping onto a second row. Long values are cut short and show in full on hover.

- **BREAKING: all of ABM's internet traffic goes through the connection you choose, and is blocked until you choose one.** After upgrading, nothing reaches the internet until you pick a proxy, a WireGuard tunnel, or Direct under Settings > Network. Direct needs an explicit acknowledgement. If you already used a proxy, it is carried over as your chosen connection. Indexers and mail, file transfer and Apprise notifications go direct unless you route them; an rclone remote ABM doesn't recognise is blocked rather than guessed at. When something is blocked, the error says so and points at the Network page.

- **Cover images are fetched through ABM** (`/media-cover/remote`) instead of your browser loading them from the source site, so covers follow your chosen connection and your browser never contacts the cover host.

- **Restoring a backup keeps your live network, proxy and security settings** unless you opt in to restoring them, so an old backup can't silently swap out your connection or switch security back off.

- **Library Import scan** is much faster on large libraries. It now reads the audio files' tags and durations several at a time and with fewer disk reads, instead of one file at a time. Every file is still read and the results are the same.

- **Library Scan** (the scheduled scan and the manual one) is faster on books with many audio files. It now checks several of a book's files at a time instead of one after another. Every new or changed file is still checked and the results are the same. Books with a single file scan in about the same time as before.

- **"Write Audio Tags" label:** the action that writes book details into audio files is called Write Audio Tags everywhere (the button, the phone menu, the Metadata settings, the Activity Log and its error message), so it isn't confused with ABM's Tags, and its button explains what it does.

### Fixed

- **A task that cannot be queued now says so instead of reporting success.** Actions that start a task answer 503 "Could not queue the task." where they used to answer success with nothing running or a generic 500. That covers creating, retrying, restarting and resuming conversions, Add Missing Books, recycle bin changes, backup exports and the catalog tasks. A book, author or series that was already created is kept, Add & Download tells you the book was added but the download could not be queued, and the refusal is written to the operation log.

- **Searches from import list syncs and upgrade sweeps are no longer silently dropped.** A search on add was lost whenever another automatic search was already queued or running, while the log said it had been queued. The same happened to the scheduled upgrade search for books below cutoff. Each now queues its own.

- **A task you start by hand is no longer merged into an automatic run of the same task.** Only a repeat scheduled, startup or upgrade-sweep run from the same trigger joins one already in flight.

- **Editing a book, author, series, indexer, download client, notification, import list or remote path mapping can now clear an optional field.** Sending `null` used to be silently dropped, so the old value stayed.

- **A bad value in a request gets a clear error instead of a server error.** Creating a folder, converting books, importing files, editing a book, saving an import list, scanning a folder, adding a series, removing a catalog entry, renaming or deleting a file and adding an exclusion now check what they are sent, so a wrong type gives a 422 naming the field and a blank scan path gives a 400.

- **Book paths are cleaned (`..` and duplicate separators) when saved, and symlink loops no longer break folder checks.** Paths already stored are rewritten the same way on upgrade. A book path with `..` used to be placed under a root folder that the rest of ABM said it was outside. Clearing logs also no longer fails on a log file that is a looping symlink.

- **Leftover temp files are handled safely.** A conversion paused for over an hour keeps its temp file and resumes instead of failing, and writing one file in a book folder no longer deletes the half-written temp file of another operation there. Only `.abmtmp` leftovers untouched for an hour are cleaned up.

- **Moving, renaming or deleting a book's files no longer races a library scan, an import, a conversion or a tag write.** A scan that reached a book mid-move could treat it as half there and leave a stray empty folder behind, and a scan could record files an import was still bringing in or a conversion hadn't recorded yet. Moving a book, moving books to another root folder, the bulk edit folder move, renaming files, deleting a file or a book with its files, and restoring a converted original now hold the book until the change is done, so a scan skips it and catches it on the next pass. They also wait for a tag or chapter write on the same files to finish instead of running underneath it, and an import and a scan wait for each other. If the files stay busy after a short wait, a move, rename or restore answers "The book's files are busy (a scan or another write is in progress). Try again shortly." and changes nothing, and importing from the Queue answers 409. A conversion that finishes while a scan is reading its book waits for the scan to move on; if the scan holds the book for more than ten minutes, the conversion fails with the reason and keeps its finished output in its work folder, and nothing in the library changes. A refresh that reaches a book in that state reports it as skipped instead of refreshed. Audible downloads land under a temporary name so a scan never sees a half-copied file.

- **Importing a finished download no longer freezes the server.** Copying the extra files, writing the sidecars and audio tags and fetching the cover happen in the background, so pages and live updates keep responding. Restoring an uploaded backup also cleans up its scratch folder without holding up the server. Starting a second import of a download that is already importing refuses with a message instead of copying it twice.

- **Writing tags, embedding a cover and adding chapters no longer overwrite each other** when they hit the same audio file at once. Each file takes one writer at a time, and a file that stays busy is reported as "being written by another task" instead of the write being lost.

- **A tag write whose cover embed fails counts the file as failed only.** It used to be counted as both updated and failed, and a book whose every cover embed failed was counted as tagged.

- **A conversion that fails on its last step no longer deletes its finished output.** If the database was locked just before a conversion recorded its new files, the finished audio was removed along with the work folder. It now stays in the job's work folder, nothing in the library changes, and the job fails with the reason.

- **A failed sidecar, audio tag or auto-tag step is reported with its reason, and the import or conversion still completes.** It shows as a warning on the task log and in the book's History, the Activity Log after a conversion, and the book's history when a book is added. A manual import now has a task log on the Tasks page, and a book whose folder is missing is reported too.

- **Sidecar fixes.** A book with no audio files gets `<book name>.opf` instead of `title.opf`, a release `.nfo` title like `Part 1:Dune` or `12:30 Club` is no longer cut at the first colon, and a book with only a release date still gets its year in the `.opf`, `.nfo` and `metadata.json`.

- **A book at position 0 in a series is a real position.** The Circle by Ted Dekker has a book 0 of 4 and now shows as "The Circle #0", with `Vol 00 - ...` in its folder name and the position kept in the sidecars. Discover refresh, the series book list and series covers also stop dropping a 0 from the catalog.

- **Names that differ only in capitals now match, accented letters included.** "CAFÉ" and "café" count as the same name (accents still matter, so "cafe" is different). Names starting with an accented capital were never recognised, so adding a series that already existed made a duplicate and author and series search results showed as not in the library. Authors, narrators, series and tags now link to the existing one instead of making a second.

- **Looking up an author by name no longer hands back a different author's ASIN, portrait, bio and books.** "Ethan Van Sciver" could come back as Jordan B. Peterson. A lookup now only accepts an exact name match (ignoring case, accents, punctuation and spacing), so a role credit like `Ricardo Cortes - illustrator` finds nobody. An author who already picked up someone else's ASIN is repaired on their next refresh, with an `author_asin_cleared` warning in the Activity Log. The repair adds no books to your library.

- **Books added to the library keep their details from the start.** A book added from an RSS import list, an author's or series' catalog, the Audible library or an Audible download, or through the API, gets its subtitle, Plus-catalogue plans, VVAB, released, explicit and abridged flags right away instead of blank until its first refresh. The catalog endpoints return these fields in each book row.

- **A refresh no longer clears a detail when the source leaves it out.** The Audible library sync, the discover refresh and the series and author catalogs keep what is stored unless there is a real new value, and an empty description or genre list counts as missing. Refreshing a book also updates its summary instead of leaving the old one showing.

- **Audible sync is steadier.** It no longer overwrites a book's details with Audible's thinner copy when Libex is unavailable, it looks books up in Libex in batches and says how many Libex could not answer for, and its progress moves ("updating N of M") instead of sitting at 5% until the account finishes.

- **Revert to automatic restores the current cover.** A refresh keeps a locked cover as the one you locked but still records the newest cover from the source, so reverting brings that one back and rewrites `cover.jpg` in the book folder to match.

- **Library Scan counts on the Tasks page match what was saved.** Changes rolled back after an error were still counted. A file whose length or bitrate can't be read is logged as a warning naming the file. A library import scan that fails reading a folder shows the one-line error instead of a stack trace.

- **Backups report what really happened.** Deleting, creating, restoring or exporting a backup the server refuses says so, with the reason, instead of reporting success, and a corrupt backup file gives a clear 400. A failed or partial restore says which step failed and what was left untouched, and restoring a database with no settings table is refused with nothing restored.

- **Pages that fail to load say so, with the reason and a Retry, instead of looking empty.** This covers the book, series and author pages, the add dialog and conversion picker, every Settings page and settings list, the Backups page, Import Lists options, the reverse proxies row, tag pickers, the FFmpeg status and the System pages (Events, Status, Tasks, Log Files, Activity Log, Calibration), on the phone versions too. A refresh that fails after a page has loaded leaves what you were looking at with a Retry strip. Import Lists options no longer fall back to defaults that a Save could write over your real settings.

- **Edit no longer wipes tags after a failed load.** If the Edit window can't load the current tags of a book, series or author, Save stays disabled instead of saving an empty list over the real ones.

- **An import list now refuses a blank, missing or non-text feed URL.** Creating or editing a list with an empty, whitespace-only, null or non-text feed URL returns a 400 instead of saving a list that can never fetch or failing with a server error.

- **Opening logs behaves.** A log that was cleaned up says it no longer exists instead of showing a load error, a task that wrote no log has no log link, a conversion's log link opens the file that was actually written even after the date rolls over, and a task's log keeps going in the same file after it closes.

- **A damaged History, Activity Log or series catalog entry no longer stops the page from loading.** Its extra details show blank and the damaged entry is noted in the log.

- **Notifications fire on every path.** An Audible direct download sends On Import, a conversion that fails unexpectedly or is refused because conversions are off sends On Conversion Failed, and a broken notification no longer fails a finished conversion.

- **Chapter times are written as numbers.** When a chapter time isn't a number, a download or conversion keeps the book and drops its chapters instead of writing that text into the chapter file.

- **Removing a Blackhole download that's already gone counts as removed** instead of failing.

- **Conversion settings CPU count and the Auto thread suggestion follow the cores the container may use**, not the host's total.

- **Settings toggles are checkboxes again on desktop,** as in Sonarr and Radarr. The phone layout keeps switches.

- **Hover actions on a book cover sit above its corner badges**, so the Audible plan badge never covers them.

### Removed

- **BREAKING (API): `GET /api/audible/diagnostics/public-ip` is gone.** It is replaced by the Public IP check on the Network page. Anything of yours that called it will now get a 404.

- **BREAKING (API): the proxy moved into the Network settings.** `GET`/`PUT /api/settings/general/proxy` and `POST /api/settings/general/proxy/test` are gone and now get a 404. The proxy is part of `GET`/`PUT /api/settings/network`, and the test is `POST /api/settings/network/proxy/test`. These `/general/proxy` routes were in released versions, so anything of yours that calls them has to move.

### Security

- **Error messages no longer carry SQL or URLs with keys.** The Libex health message, the Health page's database and FFmpeg errors, indexer RSS sync and grab errors, cover download errors, the History entries written after a book is added, download-client poll errors, recycle-bin transfers, conversion transfer-hold failures, Audible download failures and a failed startup step in the Activity Log now show a short reason, where they could include the SQL statement and its values or a full URL with an API key or passkey. Errors that quote a URL, including import list fetch errors, the recent events lists for indexers, download clients, notifications and import lists, backoff reasons and the import list's last sync message, keep only the site's address and what went wrong, so the status code, timeout or DNS failure is still there. A feed that fails to parse no longer stores or logs URLs from the feed body, and errors already stored are hidden when they are shown.

- **follow-redirects updated to 1.16.2**, fixing a published advisory in the redirect library the web interface's HTTP client pulls in: an array check that a crafted value could slip past. It's the Node-side adapter, which the browser build never uses, so it only affects the frontend's build and test tooling.

- **oauthlib updated to 4.0.1**, fixing a published advisory in the OAuth library the notification sender pulls in: the device-code token endpoint handed out a bearer token without checking the device code. It's in oauthlib's server side, which ABM never runs.

- **Saving Forms or Basic authentication with no password is refused.** The save gets a 400 asking you to set a password first, instead of locking everyone out.

- **Audible downloads only fetch from Audible's own download hosts.** A download link, or a redirect from one, that points anywhere else is refused before anything is sent.

- **Signed download links stay out of logs and error messages.** A failed Audible download no longer writes the link's signature into the log, the Activity Log or the task error.

- **Database errors no longer carry the values they were saving.** A failed write can't print a stored credential into a log or an error reply.

- **Libex lookups only send real ASINs.** A value that isn't ASIN-shaped is answered as not found and never goes into a Libex request path.

- **RSS feed URLs are encrypted at rest and hidden everywhere they are shown.** Private-tracker feed URLs carry a passkey, so an import list's RSS URL is now stored encrypted with the app key, like the list's cookie and download client and indexer credentials; existing plaintext URLs are encrypted on the next start. The import lists API returns the URL as `scheme://host/***`, and the URL is masked in the logs and in the history entries of books an RSS list added; existing history entries are masked on the next start. Saving a list without touching the URL keeps the saved one, entering a full URL replaces it, and a partly edited masked URL is refused with a message to enter the full feed URL. A URL that can't be decrypted (the key changed) stops the sync, and the list shows that its feed URL must be re-entered. An older ABM version can't read the encrypted URL, so after rolling back, re-enter the RSS feed URLs.

- **Proxy and backup export passwords are encrypted at rest.** The proxy password and each backup export target's remote password and S3 secret key are now stored encrypted with the app key, like download client and indexer credentials; existing plaintext values are encrypted on the next start and after restoring an older backup. A saved password that can't be decrypted (the key changed) is never sent, and the connection test says to re-enter it. An older ABM version can't read the encrypted values, so after rolling back, re-enter the proxy and export passwords. rclone.conf is now written owner-only from the moment it is created.

- **Addresses written in encoded forms (such as decimal or hex IPs) that point at a private or local target are now refused**, instead of slipping past the address check.
