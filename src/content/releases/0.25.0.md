### Changed

- **An import session reports a match the library already owns as in the library.** A folder matched to a book that is already in your library used to come back with the status `matched`. Its status is now `in_library`, and the match says which library book it is and whether that book has files. Recent Import Sessions counts every row once: a row waiting for you to choose is pending, and a row in the library is matched.

### Fixed

- **Metadata lookups recover after a proxy drops a connection.** If a proxy connection to Libex failed partway through setup, metadata lookups could keep timing out until you restarted ABM. The lookup that hits the failure still reports an error, but the next one starts with a fresh connection.

- **A download holding one book in two formats is measured as one copy.** A download added straight to a client with Dune.mp3 and Dune.m4b used to have both copies' runtimes added together, about twice the book's length, which could turn away the wanted book it should have been filed into or accept a longer edition. Its runtime is now one copy's, and when the copies differ by more than three minutes it has no runtime, so it is filed only by an ASIN in its files and is otherwise left for manual import. A book split into parts in different formats still adds its parts up.

- **Joining rows in Library Import no longer keeps the first row's match.** A joined row used to keep the first row's accepted match, runtime and tick, as though that match had been checked against every file. Its runtime now comes from the joined rows' own runtimes and is left empty when any of them has none, an ASIN stays only when every joined row gives the same one, and its match goes back under Needs a look, unticked, until you confirm it. A lookup that finishes after you've joined its row only suggests a match too. A match is also only accepted when every file of the book can be measured, so a book with a file that can't be read waits for review, and an edition in another language is accepted only when the files' own ASIN names it.

- **Joining two formats of one book in Library Import counts its runtime once.** Joining the Book.mp3 and Book.m4b rows added both runtimes, so the joined row's runtime was about twice the book's and no edition could match it. A joined row whose files are the same names in each format now takes the longest format's runtime, or none when the formats differ by more than 3 minutes. Parts of one book are still added up.

- **"Delete these files, keep the library copy" is checked again when the import runs.** Nothing checked it at the moment the files were removed, so a library copy that lost its files while the import waited, or a folder holding a library book's own files, could still be deleted. The import now refuses it, with nothing removed, when the library copy has no files by then ("Your library has no copy of this book to keep") or when the folder holds files of a book in your library ("This folder holds files of a book in your library"). The choice also stays with the library book it was made about: after you pick a match that is a different book in your library, it no longer applies and the row asks again.

- **Library Import accepts a match only when the files confirm it.** A suggestion used to be accepted on its score alone, so a short story could be matched to another book of its series and a lone weak result was taken as the answer. A match is now accepted only when the files' own ASIN finds it, or its runtime is within three minutes of the files and its series position or title agrees. Anything else is still suggested, but the row waits under Needs a look, starts unticked, and Select All leaves it alone until you confirm it or pick another match. The search also looks further (25 title results instead of 5, then the author's other books), ranks a book at the wrong series position well below the right one, and tries an ASIN mentioned in the files' tags on every lookup.

- **A book in several files that shares its folder with other books is one row in Library Import.** Loose parts in an author folder, or in the folder you scan, used to come up as one row per file. Files that name the same book and are numbered as its parts are now one row holding every part. Files that differ by a book or volume number stay separate books.

- **Tags written as "Title: Series, Book N" are read as a title in a series.** Audible-style album tags such as "Artificial Condition: The Murderbot Diaries, Book 2" used to give a series named after the whole text. The title, the series and the position are now read apart, a numbered or dated folder no longer invents a series out of its title, and "(Unabridged)" is dropped from a multi-file book's title.

- **A book folder holding one book in two formats gives one row per format in Library Import.** A folder with only Dune.mp3 and Dune.m4b, or the same parts in both formats, used to be one row that imported both formats as the parts of one book. Each format is now its own row, the same as when the files sit loose in the folder you scan, so you choose which copy to import. A cover or cue shared by the formats stays where it is, even when one copy is moved into the library and the other is cleared in the same import.

- **Two formats of one book in a shared folder each bring only their own file in Library Import.** When a folder held Book.mp3 and Book.m4b, each of the two rows also took the other format, so importing both added every file twice, clearing one removed the other's source, and each row's runtime counted both copies. Each row now imports, removes and measures only its own format. A cover, cue or other file with the same name goes with the book when it has only one format, and is left in place when it has two. An import whose rows claim the same folder or file is refused with nothing touched (`POST /api/library-import/confirm` returns 422 naming the shared paths), and rows that remove files to keep the library copy run only after every import in the batch has finished, so they never remove files a book in that batch was just added from.

### Security

- **Library Import's lookup and scan refuse text no real tag holds.** `POST /api/library-import/retry-match` takes at most 100 rows a request, and a row with more than 500 characters in a field (its author names counted together) comes back as an error row without being searched. A scan ignores any text tag longer than 500 characters instead of reading a title or series out of it.
