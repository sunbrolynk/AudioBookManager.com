### Fixed

- moving books to a different root folder reported success while moving
  nothing. Every book was sent with the same hardcoded source path, taken from
  a field the server has never returned, so the move either failed outright or
  skipped every book — and the result was reported as "Successfully moved N
  books" regardless, because the response was never read. Each book's source is
  now worked out from where that book actually is, so a selection spanning
  several root folders moves correctly in one go, and the result now says how
  many books moved and why any were left behind.

- moving a book whose files sit in sub-folders (`Disc 1`, `CD2`) rewrote every
  file's recorded location to the book folder itself, so those files could no
  longer be found after the move. Sub-folders are now preserved.

- a book added to a root folder other than the default recorded that choice but
  had nowhere to record where its folder would be, unless the folder happened to
  be created at the same moment. A book's destination is now always recorded
  when it is added, and creating the folder on disk is a separate step — the
  same split Sonarr uses. **Adding a book now requires at least one root folder
  to be configured**, and says so plainly rather than creating a book with no
  destination.

- the root folder list counted every book whose path merely began with the same
  characters, so a root folder named as a prefix of another reported the other
  one's books as its own — including in the confirmation shown before removing
  a root folder. Counts are now bounded at a folder boundary.
