### Fixed

- `0.15.1` got the ownership model backwards. It made an Audiobookshelf edit
  the way to opt a book out: ABM saw a `metadata.json` with no `"abm"` block
  and left that book alone from then on. That hands the source of truth to
  Audiobookshelf for any book you touch there, which is the opposite of what
  ABM is for. ABM now writes its own value and re-stamps the `"abm"` block
  every time, for any book in its catalogue, whatever the file contained
  before. The block is a provenance stamp, not a permission gate — ownership
  is decided by the book being in ABM's library, not by what is in the file.

  **If you edited a book's metadata in Audiobookshelf while `0.15.1` was
  running:** ABM stopped managing that book and will now resume. Your
  Audiobookshelf edit will be replaced with ABM's value on that book's next
  add, import, or refresh. There is no per-book opt-out yet; if you need one
  for a particular book, keep it out of ABM's library for now.

- a book correctly filed under a real, configured root folder that was not
  the default — and whose `root_folder_id` was never set to it — was refused
  by its directory listing, a manual import's conflict check, a manual import
  itself, and creating any of `cover.jpg`, `reader.txt`, `desc.txt`, or
  `title.opf`. Each of those resolved a single library path (the book's
  assigned root folder, or the default one) before ever looking at where the
  book's folder actually was, so a book filed correctly anywhere else came
  back "No root folder configured" while its files sat right there.

  Those seven checks now share one lookup that asks where the book's folder
  actually is before asking which root folder it was assigned to. A root
  folder is still required to work out where a book *should* go; it is no
  longer consulted to find a folder that already exists.
