### Added

- ABM now writes Audiobookshelf's own `metadata.json` into every book's
  folder — the file at the very top of Audiobookshelf's metadata
  precedence, above everything else ABM has ever contributed (embedded
  tags, `.opf`, `reader.txt`, even the folder name itself). Title,
  subtitle, authors, narrators, series, genres, publication year and date,
  publisher, description, ASIN, and language go in using Audiobookshelf's
  own schema, with author and narrator names written verbatim — this is the
  one channel that doesn't have to mangle a name to dodge Audiobookshelf's
  own splitting rules the way tags and `reader.txt` do. A hidden
  `.abm.json` marker sits beside it so ABM can tell its own file apart from
  one Audiobookshelf wrote or a user edited by hand: a later refresh only
  overwrites `metadata.json` when that marker is present, and leaves a
  foreign one alone.

  **`metadata.json` always writes on add, import, and refresh — none of the
  four "Create metadata files" toggles or three trigger settings in
  Settings > Metadata govern it, and there is currently no way to turn it
  off.** If you edit a book's metadata directly inside Audiobookshelf, that
  edit will be overwritten the next time ABM touches the book, because
  `metadata.json` now outranks it. If you don't want ABM controlling a
  particular book's metadata this way, delete `.abm.json` from its folder —
  ABM treats a folder without that marker as foreign from then on.

### Fixed

- `cover.jpg`, `title.opf`, `desc.txt`, and `reader.txt` were never created
  for a book acquired the normal way — indexer search, grab, download
  client, import — no matter what Settings > Metadata said. The handler for
  that path never called the metadata service at all, so none of the four
  file toggles and none of the three trigger settings had any effect on it;
  only a manual "Create" button or a library-import run ever produced these
  files. It's now wired into both a fresh import and a quality-upgrade
  replace, running after the transaction is committed and isolated from the
  import itself — a sidecar failure can never fail the import. **If you've
  had these settings enabled and wondered why your books never got a
  cover.jpg or reader.txt:** this is why. They'll start appearing on the
  next import; existing books pick them up on their next refresh or a
  manual "Create" action.
- the sidecar writer stopped creating a book's folder as a side effect of
  writing files into it. Harmless on its own before this release, since the
  only caller that could reach it with a missing folder was gated off — but
  now that sidecar generation runs on every import, an unconditional
  `mkdir` here would have quietly defeated the "Skip Folder Creation"
  library setting. It now skips with a logged reason when the folder
  doesn't exist instead of creating it.
- sidecar files (cover, OPF, desc, reader.txt, and now `metadata.json`)
  silently failed to write for a book sitting in a perfectly valid on-disk
  folder whenever no default root folder was configured. The folder lookup
  resolved a library root before ever checking whether the book already had
  a folder on disk, so the one case that doesn't need a root folder at all
  still needed one — and hit it. Fixed: the on-disk path is checked first.
- a book's `.opf` file and its embedded audio tags have always produced a
  malformed genre entry for any book with more than one genre.
  `Book.genres` is stored as one comma-joined string, but both the OPF
  writer's `<dc:subject>` loop and the audio-tag writer's `TCON` field
  wrapped that whole string in a single-item list instead of splitting it —
  so "Fantasy, Adventure" came out as one `<dc:subject>Fantasy,
  Adventure</dc:subject>` tag instead of two, and as a comma-separated
  `TCON` value instead of the slash-separated one Audiobookshelf's tag
  reader expects. Both now split the column correctly. **This doesn't
  rewrite what's already on disk** — an already-written `.opf` or a file
  that's already been tagged still carries the malformed genre value;
  regenerate the OPF or re-tag the file to pick up the fix.
