### Upgrade notes

Read these before you update. Each one is described in full under Added, Changed, Fixed, Removed or Security below.

**Before you upgrade**

- **Back up first, and know the way back.** This release drops the `root_folder_id` column from books and adds migrations after it. If the image refuses to start after the update, do not just put the old image tag back: from a container still running this image, run `alembic downgrade 4f2b9c7d1e88` first, then switch the tag. The migration refuses, and leaves the database untouched, if a book's stored root disagrees with its path.
- **Reverse proxy:** set `TRUSTED_PROXIES` to your proxy's address (`127.0.0.1` for a proxy on the same host), or you will be asked to sign in from your own LAN. An address in `TRUSTED_PROXIES` that sends no `X-Forwarded-For` or `X-Real-IP` is no longer treated as local.
- **Audible:** "Auto-add to library" is now "Mirror Audible library to ABM" and is on by default, including if you had it off, so the first sync can queue up to 25 downloads. Switch it off in Settings > Audible before syncing if you don't want that.
- **Security logs** are kept 30 days by default under their own "Security log retention" setting, whatever your general log retention is.
- **Recycle bin:** there is one bin now, set in Settings > Media Management. If recycling is off there, conversion originals are deleted permanently whatever the old Conversions switch said. The bin folder must sit directly inside a root folder or outside all of them, and a root folder can no longer be nested inside another.
- **Restore** needs your current password. Only encrypted backups restore; unencrypted backups from before 0.14 are no longer accepted, so make a new backup first.
- **Docs pages from a source checkout** need `sh scripts/fetch_docs_assets.sh` once. The Docker image does it for you.
- **Part filenames** are built one way everywhere (`Title - (Part 01) - (2020) - (MP3).mp3`), so multi-part books imported with the old layout will show as needing a rename.
- **Import Extra Files** is on by default unless you had saved it off. Scan every 24 hours and watch root folders are on by default for new installs; saved values are kept.
- Scheduled weekly Audible syncs and Discover refreshes now run on the day you picked, not a day later.
- Counts, percentages and sort order differ from before in several places (unmapped folders, Workbench filters, `parse_confidence` on a 0-100 scale, Missing Files status). That is the corrected number, not a regression.

**API and automation changes**

- **Books list:** `GET /api/books` returns each book's text once, in `description` (trimmed to a word boundary at 2400 characters), and `summary` is now null. A single book's details still carry both. `added_date` can be null.
- **Conversions:** a second conversion for a book now waits instead of being refused. Identical requests (same operation and target format) still get 409. Requests that can never do anything get 400 with a reason: merging a single file, converting to the format the book will already be in, or picking files a queued conversion will replace. Creating, bulk queuing or retrying with Enable Conversions off answers 409. Conversion jobs gain `waiting_for_job_id` and previews gain `queued_before`. `GET`/`PUT /api/settings/conversions` no longer carry the `recycleBin*` fields.
- **Recycle bin:** `PUT /api/settings/media-management` refuses a different `recycleBinPath` with 400. Change the folder with `POST /api/settings/recycle-bin/path`; `POST /api/settings/recycle-bin/path/check` is a dry run that returns `{conflict}`.
- **Basic authentication:** `POST /api/auth/login` answers 409 and cookie or token sessions are not accepted. Use Basic credentials or an API key. Basic credentials are now checked against the account, and scripts using Basic for POST, PUT, PATCH or DELETE need an `Origin` header with ABM's own address, or an API key.
- **Sessions:** changing the password or the sign-in method signs out every other session, including a restore that brings in the backup's security settings. Tokens issued before the update keep working until the first change. API keys are unaffected. Open live-update connections are closed so they reconnect.
- **Library Import:** `POST /api/library-import/scan` returns a `task_id` to poll at `/api/tasks/{task_id}`. `POST /api/library-import/session/{id}/remove-folders` now deletes any scanned row, including folders that hold audio, and answers 409 while any library import is queued or running; starting an import answers 409 while folders are being deleted. A cover choice sent for a library-book row is refused with 422. `parse_confidence` is now 0-100, and `audimeta_matches` is now `libex_matches`. `PATCH .../choices` accepts `rows`. Four unused endpoints are gone: `GET /api/library-import/progress`, `POST /api/library-import/search`, `GET /api/library-import/preview/{asin}` and `GET /api/library-import/parse-failures`.
- **Removed endpoints:** the four single-book tag endpoints under `/api/tags/book/` (404), the generic system-settings endpoint, `POST /api/settings/general/security/verify-password`, `POST /api/websocket/test-broadcast`, and `POST /api/audible/login/browser/start` and `/complete` (use `/api/audible/login/start` and `/complete`).
- **Security settings:** `GET /api/settings/general/security` returns only `has_api_key`. Read the key with `POST /api/settings/general/security/api-key/reveal` and `{"current_password": ...}`. Revealing, regenerating and saving the Security section need the current password, and saving no longer accepts an API key.
- **Secrets are not returned:** `GET /api/indexers` returns `has_api_key` and `has_cookie`; the proxy and export-target secrets return `has_*` flags; Prowlarr's `GET /api/v1/indexer` returns `********` for the API key. A blank secret on save keeps the stored one only while the address, port, TLS setting and type are unchanged.
- **Cross-origin and sockets:** POST, PUT, PATCH and DELETE allowed by the login cookie, the local-network bypass or authentication being off must come from ABM's own address, a trusted proxy's `X-Forwarded-Host`, or a CORS allowed domain, or they get 403 `cross_origin_rejected`. A script changing things over the local-network bypass without a key must now send the key. `/api/websocket` needs the same credentials as the rest of the API and subscribes only to `conversions` and `library`.
- **Request limits and errors:** request bodies are capped at 10 MiB (413), covers at 15 MB, restore at 500 MB. Error responses are fixed text and the underlying error goes to the log only, so anything matching old message text needs updating. Validation failures that were 400 or 500 are now 422 on many routes (Media Management, Conversions, Metadata, Download Handling, Indexer Options, root folders, Discover, Audible and backup schedules, malformed JSON bodies on 23 routes, and an empty `book_ids` on bulk status and monitor). `POST /api/tags` returns the existing tag for a name that exists and 422 for an invalid one. Tag names are lowercased and cannot contain spaces or commas.
- **Proxy:** when the proxy is on but its settings cannot be read, or its host is empty, requests now fail instead of going out directly, and the proxy settings request returns 500 instead of defaults. `proxy_bypass` is gone and a request that sends it gets 422. SOCKS4 is no longer accepted.
- **Metadata search:** `GET /api/metadata/search` answers 502 when Libex gave no answer, where it used to answer 200 with an empty list.
- **Other changed contracts:** `PUT /api/books/{id}` ignores `root_folder_id` and returns 200. `DELETE /api/books/{id}` reports a real `files_deleted` count and adds `files_recycled`. `POST /api/series/{id}/bulk-edit` and `POST /api/authors/{id}/bulk-edit` clear tags on `replace` with an empty list. Bulk author and series delete previews drop `orphaned_authors` and `orphaned_series` and gain `co_authors` and `other_series`; their task results move to `details.deleted_books` and `details.actions`. `GET /api/authors/{id}/catalog` returns `genres` as an array. `PUT /api/audible/settings` and `PUT /api/settings/general/backup` reject out-of-range hours, minutes and days with 422. Audible Preferred Quality accepts only High or Normal. `download/bulk` skips books you already have unless `replace_existing` is true. Auto-tag conditions with an unknown type or an empty value get 422. Settings send `mirror_audible_library` instead of `auto_add_to_library`, and gain `security_log_retention_days`, `extraFileTypes`, `extraFileExtensions` and `preferredCover`. Restore returns 403 without the current password, 400 for a plain ZIP or a backup that cannot be restored, 404 for a missing one, and 409 while another restore runs. Deleting a security log answers 403. The bare `/api` path now needs a login.

### Added

- **a download the network loses now comes back on its own.** The transfer step
  retries a dropped or corrupted stream three times inside the attempt, and when
  the outage outlasts that, the task itself is re-queued on a widening delay ,
  two minutes, then four, doubling up to an hour, until either six retries or
  six hours from the first run are spent, whichever ends first. A licence denial,
  an unowned book or a decryption failure is final and fails once, and a book
  that has arrived some other way in the meantime is dropped instead of
  downloaded twice. A download waiting for another go shows the attempt it is on
  in Tasks rather than reading as simply failed.

- **the folder browser now has a typeable path field** at the top of the
  modal, alongside the click-through listing it already had. It completes the
  way a shell's tab-completion does, one match fills in and jumps you there,
  several fill in as far as they agree, and Tab does nothing when there's
  nothing left to complete, and arrowing past the bottom of the suggestion
  list scrolls to keep the highlighted one in view. Every page that opens the
  folder browser gets it: root folders, a book's or author's edit modal, the
  library page, and Series.

- **Rename Files is now on Series and Authors, not just the library.**
  Selecting series or authors and choosing Rename Files previews and renames
  every book the selection resolves to, the same rename the library page
  already did. It's not on Backups, since what's selected there is backup
  archives rather than audiobook files, and not on Audible, since those books
  aren't in your library yet. The library's own Rename Files button now opens
  its preview dialog immediately instead of fetching every selected book's
  preview first and only then opening it, a click that used to sit doing
  nothing while those requests ran. And a book whose preview failed to load
  used to drop out of the dialog silently, with nothing on screen to say so;
  it's now named in the dialog ("Could not build a preview for: ...") and the
  rest of the selection still renames.

- **a new "Cache Changed Covers" task caches a book's or author's cover the
  moment it's set**, instead of waiting on a sweep: adding a book, changing
  its cover, a metadata refresh, an RSS import, or anything else that writes
  a cover URL queues just that cover as soon as the change is saved, so the
  grid starts serving it same-origin right away. A bulk database update now
  queues the full **Cache Covers** sweep itself the moment it commits,
  rather than waiting for the next scheduled run. If a changed cover's
  refetch fails, the stale file is invalidated instead of quietly staying on
  disk forever, so it's picked back up automatically instead of serving the
  wrong cover indefinitely.

- **an hourly "Cache Covers Catch-up" task backs up the on-arrival caching**,
  checking whether anything still needs a cover and only doing real work when
  it does, a run with nothing pending costs one indexed count and no disk
  access. It shows in Tasks every hour, no-ops included, alongside the
  existing daily **Cache Covers** sweep, which now serves as the full
  reconcile against disk (repairing anything hand-deleted from the cache)
  rather than the only mechanism catching a missed cover.

- **Download Clients and Indexers are full-width cards on a phone, with Add in
  the top bar.** Each card shows the full name, the protocol and
  implementation, whether it is disabled, its health in words, any warnings,
  the priority and the host, and the host wraps instead of running off the
  screen. The Add button stays at the top instead of sitting in a tile at the end of the list.

- **Health reads as a word, not just a colour, on a phone.** Healthy,
  Recovering, Failing, Critical or Unknown shows next to the status dot, and
  tapping it opens the health history.

- **Profiles has a phone layout.** Below 768px, Add is one button in the top bar
  that opens a sheet with Quality profile, Delay profile and Release profile, in
  place of the Add tiles and the table's own Add. The profiles are
  full-width cards with a Clone button that is easy to tap, and the chips use larger text on a phone.

- **Tags, Connect and Import Lists have a phone layout.** Below 768px, Add is one
  button in the top bar instead of a tile. The cards are full width with
  their full name, and the actions on them, such as Sync Now on an import list,
  are easy to tap.

- **A running conversion can be paused and resumed for real.** Pause on a job
  stops its encode where it is and Resume carries on from the same point, with
  nothing redone; each running or paused job has its own Pause / Resume button
  on the desktop Queue tab and on the phone row and sheet. Pause queue now
  stops new conversions and also suspends the ones running, and Resume queue
  continues only the jobs the queue stopped, so a job you paused yourself stays
  paused. A paused job's elapsed time and timeout leave the pause out, and
  cancelling a paused job stops it cleanly. After an app restart a conversion
  that was running or paused comes back paused, not failed, and does not start
  by itself; resuming it continues from the last finished part of a merge,
  split or multi-file convert, while a single file restarts from the
  beginning, and the job says which. Not available where the system can't
  suspend a process.

- **The conversion queue can be paused.** On a phone, Pause queue is a button
  in the top bar beside New conversion. Resume starts the queued jobs straight
  away. A paused queue stays
  paused across a restart and is restored with a backup. If the saved state
  can't be read at startup, the queue starts paused with a "Paused
  automatically" notice, and Resume clears it.

- **Conversions has a phone layout.** Below 768px the page is a Queue and History
  list with a counted tab control, one tap on a job opens its progress, settings,
  source files and failure detail, and a failed job has Retry right on its row.
  New conversion is a three-step sheet (Books, Options, Review) where Review is
  always shown before anything starts, and the format, quality and chapter
  choices open as pick lists instead of squeezed dropdowns.

- **The rest of the app has a phone layout too.** Below 768px, Library, Series,
  Authors and Audible Library, the Book, Author and Series pages, Activity
  (Queue, History, Blocklist), Wanted, Calendar, the four Discover pages,
  Library Import, Add New, Cover search, Interactive Search, the Add sheets and
  the Book Detail dialogs are laid out for a thumb: one column, large tap
  targets, no sideways scrolling, and sheets instead of squeezed dialogs. Books
  show as the same compact row everywhere, with a sheet of actions behind it.
  Calendar has an agenda list and a view picker. Light and dark are both
  designed. On the Book, Author and Series pages, values sit right-aligned
  beside their label, and a multi-part value (authors, narrators, publishers)
  lists its names one per line. Desktop looks the same as before.

- **On a phone, pull a page down from the top to refresh it.** Every page can
  be pulled down to reload what it shows, alongside the live updates. A spinner
  shows while it works, a screen reader announces it, and a toast says how many
  parts failed to load. The same Refresh is a row in every page's ··· More
  menu. A settings page you are editing keeps what you have typed when the data
  refreshes underneath it.

- **Sort, filter and view sit in a strip of pills on a phone.** Library, Series,
  Authors, Audible Library, a series's book list, the table pages, Discover,
  Calendar and Events keep a strip under the header with a Sort pill, a
  Filter pill (highlighted while a filter is on, including saved and custom
  filters), a List / Poster / Table switch and the rows-per-page choice. Each
  pill shows its current value, so you can see how a page is sorted and
  filtered without opening anything. This replaces the "Sort and view" sheet.
  The totals come at the end of the list as a small block that scrolls with
  it, each colour key beside its own count (for example "Downloaded: 249"),
  instead of inside that sheet.

- **Settings opens as a grouped list on a phone.** Instead of a stack of big
  link cards, the Settings home is three groups, Library (Media Management,
  Profiles, Metadata, Tags, Conversions), Sources (Indexers, Download Clients,
  Import Lists, Audible, Discover) and App (Connect, General, UI). Each row has
  an icon, its title, a line saying what the page is for and a chevron. The sidebar and the desktop layout are unchanged.

- **"Search all wanted" is in the More menu on a phone.** It no longer takes up
  room in the header.

- **Library's filter offers "Downloaded" on the desktop too.** It was only there
  on a phone.

- **Audible settings has a phone layout.** Below 768px the page is grouped: the
  security notes in one card, Connect New Account in its own card with the
  marketplace as a pick list and a full-width Connect button, and each connected
  account in a card of its own. An account's actions sit behind a ··· button
  that opens a sheet, and Disconnect asks Yes or No right in the card. Re-auth,
  the sign-in steps and Run All Tests are full-width buttons, and the sync
  time uses pick lists. Desktop keeps its layout.

- **Audible settings is easier to use with a keyboard or a screen reader.**
  Disconnecting, signing in and re-authenticating keep keyboard focus where you
  are and announce when they succeed. Connect stays disabled until the
  marketplaces have loaded, and on a phone Run All Tests says why it is disabled.

- **The Public IP Refresh button is easier to tap on a phone.** On the Audible and
  General settings pages, and unchanged on desktop. The Proxy Active badge on
  both pages is darker in light mode.

- **The System pages have a phone layout.** Below 768px, Status, Activity Log,
  Log Files, Calibration and Updates are grouped lists and cards with large tap
  targets. Status has Health as a group, with long messages clamped, and Disk
  Space as compact cards. Activity Log is compact rows with a meta line and one
  Details expander for Before, After and Details, paged like the other phone
  lists. Log Files has a group per category, two-line file rows showing size and
  age, a tap to open the viewer and a ··· button for View, Download and Delete.
  Calibration is a group per operation. Updates is one card per release.
  Desktop is laid out as before.

- **While Live is on, the log viewer follows the newest line.** Scrolling up
  pauses it and scrolling back to the bottom resumes it.


- **Audible syncs can mirror your Audible library into ABM.** The old "Auto-add
  to library" setting is now "Mirror Audible library to ABM" and is on by
  default. After each sync, ABM takes the purchases and the books Audible gave
  you for free (free trial, member gifts, free Originals) that it doesn't
  have, or has as wanted with no files, adds them and downloads them. It does
  at most 25 books per sync, in the same order every time, so a big library
  finishes over a few syncs. Podcasts are never mirrored or stored, a book
  removed from Audible stays in ABM and is left alone, and so are accounts
  that need re-authentication. If the root folder is nearly full (under 5%
  free) nothing is queued and the sync says so. A book whose download keeps
  failing is held back for 1, 6, then 24 hours so it can't use up the 25.
  Turning it on asks first, with a count from `GET /api/audible/mirror/preview`.
  A download now always adds the book to the library if it isn't there yet.

  **Upgrading:** the setting was renamed and is on by default, including if you
  had turned auto-add off, so the first sync after updating can queue up to 25
  downloads. Switch "Mirror Audible library to ABM" off in Settings > Audible
  before syncing if you don't want that. Anything scripting the settings API
  must send and read `mirror_audible_library` instead of
  `auto_add_to_library`.

- **Scanning and watching are on by default.** New installs scan the library
  every 24 hours and watch the root folders for changes. Anything you have
  already saved, including Disabled and off, stays as it is. A root folder
  the system can't watch, such as one past the inotify watch limit, is logged
  and skipped instead of stopping startup.

- **Website and Discord on the Status page.** More Info now lists the home
  page and the Discord invite next to the source and metadata links, instead
  of only those two.

- **Security logs have their own retention setting.** They used to be
  deleted under the general log retention, so a short general value could
  wipe the fail2ban/audit trail. Now logs/security/ is only cleaned under
  "Security log retention" in General settings > Logging: at least 7 days
  (30 by default), or 0 to never delete them, with a Never Delete tick. A
  saved value below 7 is rejected, and the cleanup itself never deletes a
  security log younger than 7 days. If the stored value can't be read, the
  security cleanup is skipped and says so in the log, instead of guessing.
  The settings API gains a `security_log_retention_days` field; leaving it
  out of a save keeps the stored value. After updating, security logs are
  kept 30 days even if your general log retention is shorter, so they may
  take more disk; lower the setting (7 at least) if that matters.
  The log file the security logger is writing to is never deleted, however
  quiet it has been.

- **Add New can add a whole author or series.** The search has two new modes,
  Author and Series, that find the authors and series themselves; the old book
  modes are now called "Books by author" and "Books in series". Adding one
  builds its catalog and adds its books as wanted according to Monitor: All,
  Future, Missing (the default) or None. You also pick the root folder, the
  quality profile and whether books that appear in the catalog later are added
  too (on by default for a series, off for an author), and can start one search
  for everything it added. The add runs as a background task with a progress
  toast. A series result shows the same cover the Series page would: a
  library series its own, one you don't have yet its first book's. On a phone
  the search mode is a compact dropdown above the search box and the add
  dialog fills the screen. A
  series you add stays, even with no books, until you remove it, and while
  an add is still running the delete cleanup keeps the series and authors of
  the books it is bringing in.

- **An author or series you already have can fill in its missing books.** In
  the Author and Series search modes, a result already in your library shows
  "In Library" with an "Add missing books" action and a link to its page. The
  action takes the same Monitor and search choices: it adds the catalog books
  you don't have as wanted, skips the ones you do, and saves the Monitor New
  Books choice on that author or series.

- **Library Import can now hardlink your files instead of copying or moving
  them.** A hardlinked book takes no extra disk space and leaves the original
  exactly where it was. Hardlink is offered as the Media Management "Library
  Import" default and in the Add to Library dialog whenever the default root
  folder has been checked and supports hardlinks; otherwise it is shown greyed
  out with the reason underneath. A file that can't be linked (it sits on a
  different drive, or the filesystem refuses the link) is copied instead,
  never moved, and the finished import says how many files were copied that
  way. A book's extra files (cover, .opf, notes) are hardlinked the same way,
  with any that can't be linked copied and counted; a symlink in the source
  is copied rather than linked. When ABM rewrites cover.jpg, desc.txt,
  reader.txt, the .opf or metadata.json in a hardlinked book, it writes a
  fresh file, so the original you imported from is never changed through the
  link. An import that had problems or copied files shows the Workbench's
  summary as a warning when it finishes.

- **the Import Workbench shows each folder's cover and extra files, and lets
  one import change them.** The inspector puts the folder's own cover beside
  the matched edition's, each with its pixel size; the one the book will get
  is bright, and one click on the other picks it. A folder with several
  images shows its best-named one with a "+N images" count that opens the
  rest, and art embedded in the audio can be picked too. The chosen cover is
  saved as the book's cover and never listed again. Below it, "Extra files"
  lists every other file the folder carries under the same name as its
  Media Management switch, with what the import does with it: other cover
  images are unticked and, once ticked, say "Not the cover · imports as
  cover-original.jpg"; release junk is listed unticked; ABM's own files are
  locked. Everything starts from the Media Management settings, a dot marks
  a choice that differs from them, and choices are saved with the session.
  "Apply this cover and these file choices to the N other selected" copies
  one folder's choices to the other ticked folders, by file type, and
  carries a cover preference only if you actually picked a cover. An image
  ABM can't read is shown as "can't be read" and can't be picked. A row
  that adds files to a book already in the library, or that removes or
  keeps instead of importing, shows no extras list or cover picker and says
  why; a cover choice sent for a library-book row is refused with a 422.
  A folder left alone is imported exactly as the settings say.

- **the Import Workbench's folder list can now be sorted, filtered and
  rescanned, and the sort and filter are remembered.** Folder order is still the default, so nothing moves while
  matches are being looked up, and neither a sort nor a filter reorders a
  row while a lookup is still landing under it. Select All only ticks the
  folders a filter is showing. Rescan looks at
  the scanned folder again and adds the folders that were not there before,
  without touching a single choice already made on the others.

- **a series's own page now has a Refresh Series button.** The book-list page
  for a series (Library → Series → a series) gets a leading "Refresh Series"
  action, queuing the same scoped metadata refresh the Series list's
  hover-and-overview Refresh action already did, now available without
  leaving the series to go back to the list. It's disabled while a refresh for
  that series is already running, and the book list refreshes itself once the
  task completes.

- **each folder in the Import Workbench list now shows its own name, its file
  count and how confident the match is.** The row used to show only the parsed
  title and a status badge, so you had to open every folder to see how many
  files it held or how sure the match was. The line under the name reads like
  "3 files · 95% match"; the confidence is left off once you pick a match
  yourself, since the scan's number described its pick, not yours.

- **library imports now go through an Import Workbench instead of the old
  results page.** Scanning a folder opens one page with every book: its files
  and matched edition laid out side by side, and anything still unmatched
  keeps looking itself up in the background instead of sitting stuck. Each
  book's other candidate editions are listed too, with the reason behind
  every one, which fields agree with the files and which don't, not just a
  checkmark or a dash with no explanation. Each row gets its own decision
  where one's needed, Add offers Copy or Move, and once an
  import is running the page stays locked until the list has actually caught
  up with what imported, so a second click can't land on rows that are
  already stale. Whatever's decided on the page is saved as it's chosen and
  is still there if the page gets reloaded partway through. If a save fails,
  the page says whether it's already retrying on its own or waiting for you
  to retry. A folder holding several books can be split into one row per
  file, each looked up under its own file name, and rows that are really
  parts of one book can be marked and merged into a single book that
  imports every file. Both ask first, never touch anything on disk, and are
  kept if the page is reloaded. Before anything runs, the Add confirmation lists
  every row under what will happen to it, names the root folder imported
  books go to, and says whether removed files go to the recycle bin or are
  deleted outright. Searching for a match by hand also turns up books by an
  author or in a series of that name, not only books with that title.
  On a phone the folder list and a folder's details take turns filling the
  screen, with a way back to the list, instead of squeezing side by side, and
  Split and join are big enough to tap and sit beside the status, so tapping
  a folder opens it rather than marking it. If an import session has gone, its
  page offers Start New Import. Whether an import copies or moves your files
  now defaults from a new Library Import setting in Settings → Media
  Management (Copy unless you change it); the Add confirmation still lets any
  one import pick the other.

- **the Import Workbench compares narrators and shows more about each
  edition.** A scanned folder now carries the narrator its tags or folder
  name give, and the inspector sets it beside the matched edition's
  narrators, flagging them when none agree. The matched edition's
  subtitle, publisher and whether it is Virtual Voice are shown there too.

- **an ASIN scraped from a comment or description no longer decides a match on
  its own.** Only a dedicated ASIN tag counts as one; a comment ASIN is kept as
  a hint, and the library scan only lets it decide a match when the matched
  title agrees with the folder's own. A completed download is handed to the

### Changed

- **a book's root folder is no longer its own stored setting, it's worked out
  from where the book's folder actually is.** The database column that used to
  hold it is gone, along with the half-dozen places that wrote to it
  independently; every one of them now asks the same question the same way, by
  checking which configured root folder the book's path currently falls under.
  The one-time migration that drops the column refuses to run, and leaves the
  database untouched, if it finds a book whose old stored value disagreed with
  its path, that's a sign of stale data that shouldn't be resolved
  automatically, and the previous image tag is a safe rollback if it happens. A
  book that had no root folder recorded before but does resolve one from its
  path picks one up as part of the same migration, which logs which books those
  were.

  **That safe-rollback claim covers only the refusal case above.** Once the
  migration succeeds, the column is dropped, no error raised, reverting to
  the previous image tag by itself is not safe: that image runs its own
  migration step on every start, and it can't reconcile a database already
  stamped past a revision it doesn't recognize, it fails immediately with
  `Can't locate revision identified by` whatever the database is currently
  stamped at, and the container never gets far enough to start the app
  itself, so what you'll see is a crash-looping container, not a running app
  with broken queries. Downgrade the schema before you change the image tag,
  not after, run `alembic downgrade 4f2b9c7d1e88` against the database from
  a container still running *this* image, **not** `alembic downgrade -1`:
  this release adds migrations after the one that drops the column, so
  stepping back only one revision leaves the column dropped and the database
  still ahead of what the previous image can run. `4f2b9c7d1e88` is the
  previous image's own migration tip; downgrading to it undoes this
  migration and everything layered on top of it in this release, matching
  what that image actually knows. The downgrade re-adds the column and
  re-derives each book's root from its current path against whichever root
  folders are configured at that moment, not the value that was stored
  before the column was dropped, if you've added or removed a root folder
  in between, check the result, because a book's restored root folder may
  not match what it originally was.

  **`PUT /api/books/{id}` no longer accepts `root_folder_id`.** No book edit
  screen in ABM has ever sent it, so nothing in the UI changes, but if you've
  automated a root-folder move by sending it to this endpoint directly, that
  request now returns 200 and does nothing at all, silently, rather than
  failing or moving anything. Use the library's bulk move action instead.

- **adding a root folder is now validated before it's accepted**, instead of
  only failing later in confusing ways. A folder this process can't write to is
  refused up front, and the message names both the path and the OS user ABM is
  running as, the usual cause is a container UID/GID that doesn't match the
  folder's owner on the host. A folder under an OS/system directory (`/etc`,
  `/var`, `/usr`, and the like) is refused outright; nothing legitimate lives
  there.

- **the folder and filename parser is substantially more accurate.** Measured
  against a 716-case labelled set of real library paths, it now reads every
  field correctly for 705 of them, up from 264. Four changes account for most
  of that, and none of them is a list of special cases:
  - **what the source wrote is kept.** A position written `Vol 02` is stored as
    `02`, not `2`, box sets and omnibuses use positions like `1-7`, so there
    is no safe way to renumber one without breaking the other. A title that
    ends `, Book 2` keeps it, because that is how Audible names the book and so
    it is how metadata lookups find it. A series genuinely called
    `Something Series` keeps the word "Series", which was previously trimmed
    off every series name whether it belonged there or not.
  - **a title is whatever is left once every other field has claimed its part
    of the name.** A leading year, a volume number, a series name repeated in
    brackets on the end, each is removed only because something else already
    identified it, never because it matched a pattern. So a title that is
    genuinely a number, or genuinely contains a year, survives intact.
  - **an explicitly labelled position beats an inferred one.** `Vol 02` in a
    folder name is trusted over a bare number on the end of a title, which may
    just be part of the title.
  - **two authors credited together are read as two authors**, while a single
    name written surname-first stays one person. A name that does not look like
    a conventional one, a handle, or a pen name with digits in it, is
    accepted rather than discarded.

- **the filename parser knows the exact folder an operation is scoped to when
  the caller has it, instead of guessing.** A library scan, matching a manual
  import, and matching a completed download against its download-client
  output folder now all pass that folder through, and it's stripped from the
  path exactly rather than by checking the leading path segments against a
  fixed list of common container names (`downloads`, `media`, `mnt`, and the
  like), a folder whose name wasn't on that list, or that happened to share a
  name with an author or series, could throw the guess off before this. It
  also now recognizes a file already named the way ABM's own format-conversion
  output is, `Title - (Year) - (FORMAT)`, and reads the title straight off
  that instead of falling back to guessing from folder structure.

- **every remaining "Audimeta" reference is now named Libex**, ABM's actual

  "Audimeta" was a stale name held over from before ABM moved to it. This is a

### Fixed

- **Pages no longer start underneath the fixed header on a phone.** The top of Settings > Tags sat under the bar with no way to scroll up to it, and a page that fit the screen could still be dragged up behind the header. Every page now reserves the same space for the header. Expect the very top of most pages to sit a few pixels differently than before; that is the corrected spacing, not a regression.

- **several lists sorted the wrong way**, the folder browser put lowercase
  folder names after "_"-prefixed ones instead of natural, case-insensitive
  order; the conversion preview and a manual import scan ordered multi-part
  files lexically (so "part10" came before "part2"); download clients had no
  tiebreak below priority, and indexers broke ties by name case-sensitively
  with no further fallback; tags, auto tags and import lists had no defined
  order at all; and the manual import preview could put files out of order
  because it compared part numbers and filenames inconsistently.

- **the README's Documentation section linked to three files that never
  existed**, `docs/CONFIGURATION.md`, `docs/API.md` and
  `docs/ARCHITECTURE.md`, each marked "(TODO)" since there was never a `docs/`
  directory to put them in. It now points at what's actually there instead:
  the interactive API reference served at `/api/docs` on a running instance,
  and this changelog. The `DOCS_ENABLED` variable that governs whether those
  API docs exist at all was never documented anywhere; it's now in the
  README's environment variable table and `.env-example`, alongside a note on
  the new Documentation line that the reference disappears when it's off.

- **the root folder count on Library Import and Settings could take several
  seconds to show up, and sometimes never showed a number at all**, on a
  root folder backed by a slow mount, every visit to either page walked its
  filesystem fresh, and a walk slow enough to miss its own timeout came back
  as an unhelpful "unknown" instead of the count that was already known. The
  scan now runs at most once per root folder per minute, including while
  the mount keeps failing, so a stuck scan is never retried on every single
  page view, and a page view within that window gets the answer instantly.
  A scan that fails after a count was already known keeps showing that
  count, marked with how long ago it was captured ("as of 2m ago"), rather
  than blanking it out or quietly passing off an old number as current. The
  count also updates itself the moment a book is added or removed under that
  root, instead of waiting out the full minute. Both pages now read from the
  same hook instead of each fetching on its own, and show an explicit "could
  not load root folders" message rather than the empty-library message when
  the fetch itself fails.

- **a page with nothing left to scroll to could still be dragged up behind
  the fixed header on a phone**, most visible on Tags' empty state. A phone
  browser's full-height measurement includes the space its address bar takes
  up, so a page that fit the visible screen was still given room to scroll.
  The app shell, and the "Something went wrong" screen a crashed page falls
  back to, now size to what's actually on screen.

- **Library Import could decide two unrelated books were the same edition
  because they ran about the same length.** A book now has to plausibly be
  the same by title, author and series before its ASIN or runtime decides
  the edition: a matching ASIN is always the same book, a different ASIN
  always a different edition, and without an ASIN the runtime has to agree
  to within a few minutes.

- **Library Import no longer marks a folder as a book you already own on a
  title and series match alone.** A folder with neither an ASIN nor a runtime
  can't say which edition it is, so it's now offered as a new book instead of
  being claimed by whichever edition is already in your library. The same
  goes for a book added straight to a download client: one whose name carries
  no ASIN is left for you to import by hand rather than filed into a wanted
  book with the same title. Folders looked up after the scan also keep their
  own runtime and year now, so an untagged folder is still told apart from an
  owned edition by its length.

- **a download added straight to a client, with no ASIN in its name, is once
  again filed into the wanted book it matches automatically.** Once its files
  are on disk, the download's own runtime is read straight off the audio,
  skipping any bundled sample or trailer, and used the same way an ASIN would
  be to confirm the edition, close enough to a wanted book's own runtime and
  it's imported without asking; too far off, files the probe can't read yet,
  or more than one book of that title in the library, and it's left for
  manual import instead of guessing which one.

- **a single series' or author's own edit screen only ever added tags, never
  replaced them, though the field looked identical to a single book's own
  tags field, which does.** It also started empty every time, with no way to
  see what was already on the scope's books. It now seeds from what's
  actually there and saving sets tags to exactly the box's contents, the same
  meaning a single book's field already carried. Applying a tag whose name
  differs from an existing one only by case now reuses that tag everywhere,
  instead of creating a case-variant duplicate.

  **`POST /api/series/{id}/bulk-edit` and `POST /api/authors/{id}/bulk-edit`
  now clear tags on an explicit replace with nothing.** Sending `tag_action:
  "replace"` with an empty `tags` list used to be silently ignored, the
  whole tag step was skipped and the scope's tags were left untouched. It's
  now treated as what it says: replace with nothing, which clears every tag
  in the scope. ABM's own UI only ever sends `tag_action` when its tags field
  is shown, so this doesn't change anything you'll see there, but if you've
  automated against either endpoint and relied on an empty replace being a
  no-op, it isn't one anymore.

- **"no root folder configured" arrived as a blank error.** The exception
  behind it carried no message at all, so an operation that failed for that
  reason surfaced an empty string, an empty red box in the UI, an empty
  `error` on a failed task, and nothing in the log to say what was wrong. It
  says what it means now. The same change also settled where a book's folder
  should go: the half-dozen places that each worked it out their own way now
  ask one function, which uses the book's own root when it resolves and falls
  back to the default root otherwise.

- **the task list filled up with sweeps that had nothing to do** (#38). A
  timer runs the completed-download check and the pending-grab retry whether or
  not there is a download client to check, and every run that found nothing left
  a row behind, thousands of them over a retention window, burying the runs
  that actually did something. A sweep that finds nothing now leaves one row, so
  the list still shows when it last ran and that it had nothing to do, and the
  earlier copies are dropped. Runs that did work are never touched.

- **the library page now ends with a summary of what it holds** (#40), books,
  monitored against unmonitored, how many files, and the space they take. Sonarr
  and Radarr both end their index this way, and someone arriving from one of
  them looks for it there. It counts what is on screen, so it follows a filter
  or a search rather than always reporting the whole library.

- **the Audible library could not be filtered down to Wanted books** (#39).
  Every row already showed a Wanted badge, a book ABM is tracking but has no
  files for, and the filter list offered everything except that one. It is
  there now, beside In Library and Not in Library.

- **a series sorted by title put its first book last** (#37). "Book 10" sorted
  before "Book 2", because plain text order compares one character at a time and
  "1" comes before "2" long before either is read as a number. Every list that
  sorts by name now reads numbers as numbers, the library, the queue, manual
  import, interactive search, conversions, the author page and library import ,
  through one comparator rather than sixteen copies of the old one. Same option
  Sonarr uses.

- **moving a book's folder accepted any path on the machine.** The endpoint
  takes a source and a destination, creates whatever parent directories the
  destination needs, and moves the folder, with no check that either end was
  inside a root folder you had configured. Both ends are now required to be, so
  a book cannot be planted outside your library and a directory from elsewhere
  on the machine cannot be carried into it. The same guard the root-folder
  settings already use.


- **a conversion's own log file was the one log in ABM that did not redact
  credentials.** Every other log sink strips anything that looks like a key,
  token or password before it reaches disk; the per-job conversion log was
  created without that filter, so a secret appearing in a conversion message or
  its details was written out in the clear. It is filtered now, like the rest.

- **two failures while adding a book were logged where nobody would see them.**
  When looking up an author upstream failed, the book was still created without
  that author's details and the only record was at debug level, which is off by
  default, so the author simply appeared bare with no stated reason. Both are
  warnings now, matching how the same failure is reported everywhere else.

- **the Tasks page showed `cache_covers` as a raw name.** The cover-caching task
  was missing from the table of display names, so it read as its internal
  identifier rather than "Cache Covers".

- **A long task could be reclaimed as abandoned when the database was busy.** Its progress update could be dropped, and with it the lease that keeps a healthy task running. The update now retries, and a failure to record it is logged without failing the task.

- **The cover-caching task now leaves a log and a proper record in Tasks.** Book covers and author images are handled separately, so one failing no longer takes the other down or discards the work already done.

- **an author you follow but own no books by was counted twice in a refresh.**
  The same author appeared in the results as both kept and updated, and inflated
  the updated count. Reported once now, as kept, with the number of books in
  their catalog. Their catalog is still refreshed on every run, which is the
  whole point of following an author before you own anything by them.

- **a root folder could be added at a path that could then never be deleted.**
  The check that admits a path and the check that allows deleting its files
  were two different rules, so `/mnt`, `/media`, `/opt` and `/srv` could be
  added as root folders and would then refuse the delete-with-files option
  forever, with no explanation. The delete rule also inferred safety from how
  deep a path was, "a real library lives at least two folders down", which is
  wrong for the most common container setup there is: a library bind-mounted
  straight onto `/audiobooks` was refused. Both ends now apply one rule that
  names the dangerous mount points instead of guessing from depth. Bare system
  mounts are refused everywhere; a dedicated mount works everywhere.

- **with more than one Audible account connected, downloads could be queued
  under an account that did not have the book.** Selecting 231 books from one
  account's shelf and hitting Add & Download added all 231 and failed all 231,
  each with `Book with ASIN <X> not found in Audible library`, the account was
  chosen once for the whole batch, and a request that named none fell back to
  whichever active account happened to come first. Every book is now resolved
  to an account that actually owns its ASIN, on every path that queues a
  download. An ASIN can belong to several accounts at once, so the account the
  library page is filtered to is now sent with the request and used wherever it
  owns the book; otherwise the lowest-numbered owning account is, so the same
  request always resolves the same way. A book no active account owns is
  reported as a skip that says so, rather than queued as a download that could
  only fail.

- **a library scan asked the metadata service for the same series once for
  every book in it.** A real 457-folder library sent 383 series lookups for
  **121 distinct series**, the same question, hundreds of times, and every one
  of them a request the service had to answer. Each client now remembers what
  it has already been told, for its own lifetime and no longer than five
  minutes. Nothing is shared between operations: every caller builds its own
  client, so a refresh still goes and asks. Only real answers are kept, a
  dropped connection is a fact about the moment, not about the record, and
  repeating it would turn one failure into a scan's worth.

- **deleting a book could report a failure for a book it had already
  deleted.** Tidying up the authors and series left without books runs after
  the book itself is durably gone, and a failure in that step was reported as
  the delete failing, inviting a retry of something already done. It is now
  logged and the delete reports what actually happened.

- **a folder the scan matched by itself never said the book was already in your
  library**, so the row went in with no badge and no question, while searching
  for the same book by hand showed it as In Library plainly. Only the manual
  search had ever marked a result as one you own; the scan's own matching never
  did. It does now, on every candidate and from every search it tries, so an
  automatched row asks what should happen the same as a hand-picked one.

- **a Library Import folder could settle on the wrong book from the right
  series.** Matching stopped as soon as a candidate scored well enough, but a
  book from the same series by the same author at the same position scores well
  on all of that while naming something else entirely. A folder named *Harry
  Potter and the Sorcerer's Stone* settled on the *Philosopher's Stone* at 74%,
  and the search that would have found the right edition never ran, because the
  score alone was judged good enough. The leading candidate's title now has to
  agree with the folder's before the search stops looking; where it does not,
  the whole-phrase search runs as well. The same folder now matches the right
  book at 93%. Titles are compared with the punctuation that separates a folder
  name from a store listing set aside, an ampersand for "and", a dropped comma,
  an initial without its full stop, so this asks for a second search only where
  the books genuinely differ: 27 of 460 folders on a real library.

- **the import log described a run that removed a folder as an import of
  nothing.** Choosing *delete these files, keep the library copy* and running it
  produced `Imported 0 of 1 books` alongside `SUCCESS`, which reads as a failure
  that somehow passed. It now says what happened, `1 folder(s) removed (1
  file(s))`, counts the removals separately from the imports, and reports
  imports out of the rows that were actually meant to be imported.

- **a Library Import row now asks what should happen whenever it cannot simply
  be imported, and the import will not start until you have said.** Before, a
  folder matching a book that already had files was simply locked as "Already
  Imported" with nothing you could do about it, and a folder matching a book
  with no files was swept in with everything else. A folder with no audio in it
  had the opposite problem: unless it happened to match a book already in your
  library it was offered **Import** and ticked for you by default, nonsense for
  a folder with nothing to import, and it meant the folders most likely to need
  clearing away were the ones this page could never clear away. Each situation
  now states itself and offers only the actions that fit it: import and rename;
  delete these files and keep the library copy; or, for a folder with no audio
  in it, **delete this folder and its contents**, listed for you first, since a
  book in a format ABM cannot read looks exactly like a folder of leftover
  artwork and sidecars until you can see the names. That last action now
  genuinely removes what is there, rather than quietly doing nothing whenever
  the folder was not already empty. Every deletion here honours your recycle
  bin, so nothing is unrecoverable when one is configured, and refuses outright
  rather than emptying a configured root folder, a protected system path, or a
  folder that turns out to hold audio after all. **Add to Library stays disabled
  while any such row is unanswered**, so none of it is swept along, though only
  the rows you have ticked can hold it up, since a row you are not importing is
  not one you need to have decided about, and a folder with no audio is never
  ticked for you or taken by Select All.

  Every import lands at the name ABM chooses. Keeping a folder where it lies is
  deliberately not offered, a library where some books sit at ABM's name and
  others wherever they were found is not one ABM can reason about.

- **three settings pages failed silently.** Metadata, Conversions and Discover
  had no error handling at all: a save that the server refused looked exactly
  like a button that did nothing, the change stayed on screen, unsaved, with no
  word of why. All three now say what went wrong.

- **the settings pages showed you "Request failed with status code 500" instead
  of what went wrong.** Axios writes that same sentence for every failed
  response, and thirty-six places passed it straight to the screen, so a root
  folder that could not be written to, a download client that refused a
  connection, an indexer that rejected an API key all read identically and told
  you nothing. Every one of them now shows the server's own message where there
  is one, and the specific message the page already carried where there is not
  ("Failed to load download clients", "Failed to regenerate API key"). An error
  raised inside ABM rather than by a request still shows its own text, which is
  the part that was worth keeping.

- **the log endpoints confined a request to the logs directory by comparing the
  text of the path, which let a sibling directory whose name merely started the
  same way through.** With logs at `/config/logs`, a request for
  `/config/logs-backup/secret.txt` satisfied the check, on the endpoint that
  reads a file, the one that downloads it, and the one that **deletes** it. The
  three endpoints now share one check that compares path components instead of
  characters, so a sibling is outside no matter what it is called.

- **a book split across many files could arrive as one row per file.** Whether
  a folder holds one book in pieces or several separate books was decided by
  stripping eleven different numbering patterns off each filename and comparing
  what was left, which missed any shape not on the list: a folder of
  `Death Masks 001-109.mp3` through `109-109.mp3`, one book, became **109
  separate rows**, and `Chapter 01.mp3` through `Chapter 52.mp3` became 52. The
  rule is now a single idea instead of a list: reduce each filename to the
  words that say *which book* it is, discounting the numbering and the words
  every audiobook file uses, part, disc, chapter, intro, and if the files
  disagree about nothing, they are one book. Where the filenames name no book
  at all, the folder is the only thing that does, and they are one book too.
  On a real 649-row scan this removed **192 wrong rows**, while a folder
  holding a whole series in separate files still gets a row per book. It also
  corrected the reverse mistake, where two genuinely different books that
  happened to share a long prefix were merged into one row.

- the "unmapped folders" count on Settings > Media Management and the Library
  Import page could be wrong in three separate ways. A folder was matched to
  your library partly by whether its name merely contained, or was contained
  by, a book's title, a book named "It" hid an unrelated real folder named
  "Bitten" from the count entirely. An author folder holding loose audio of its
  own read as "mapped" whenever a real book's folder happened to sit one level
  below it, hiding exactly the stray files this count exists to surface. And a
  scan that couldn't finish, a slow or dropped network mount, reported the
  count as `0`, indistinguishable from a library with nothing to import. All
  three are fixed: title matching is gone, an ancestor folder no longer hides
  what's loose inside it, and a scan that can't finish in time now shows as
  unknown instead of zero. **Counts will read differently than before on an
  existing library, that's the corrected number, not a regression.**

  Two more refinements to the same count landed in the same change: matching a
  folder to your library now goes by path alone, a folder whose name happened
  to contain a book's ASIN, or that matched wherever a book was originally
  imported from even after that book moved elsewhere, no longer counts as
  mapped just for that. And a folder no longer needs audio in it yet to be
  counted at all, any folder with no subfolders of its own counts now, filled
  or still empty, so an author or series folder you created and haven't filled
  in shows up too, the same way Sonarr's own scan treats it.

  **The recycle bin path now has to sit directly inside a root folder, or
  entirely outside every one of them**, Settings > Media Management refuses
  to save one nested two or more levels deep, with a message saying why. If
  yours is already set up that way, move it: a recycle bin buried further down
  gets skipped over during the scan, which leaves its own parent folder
  looking empty and wrongly counted as unmapped.

- adding, removing, and setting a default root folder on Settings > Media
  Management now show you when one of those fails. All three used to fail with
  nothing on screen at all, the dialog just sat there, because the request's
  error response was never read. They now display the server's actual message.
  Setting a default no longer closes its dialog before the request has
  finished, which previously made a failed attempt look like it had worked.

- `DELETE /api/settings/delete-folder` checked the folder you asked to delete
  against a short list of exact paths, so anything one level further down one
  of those was still deletable, `/etc/sudoers.d`, for instance. It's now
  checked the same separator-bounded way the rest of ABM's system-folder guards
  work, so a subdirectory of a protected path is refused too, and the path is
  resolved before the check so a symlink can't be used to point it somewhere
  the check wouldn't recognize.

- two probes ABM runs against a root folder, whether it supports hardlinks,
  and now whether it's writable at all, created a check file under a
  predictable, guessable name and opened it for writing directly. A symlink
  planted at that exact name ahead of time would have had its target silently
  overwritten instead of the probe file being created fresh. Both now use a
  proper temp-file API that refuses to follow an existing symlink.

- delete, refresh, and import now all ask the same place which root folder a
  book belongs to, instead of five separate copies of that logic that could
  each answer differently; and deleting a book's files when no root folder can
  be resolved at all now says so instead of silently doing nothing.

- removing a root folder with **Delete the books and their files** checked
  wiped every file at that path but left the books that had lived there in the
  library anyway, now pointing at nothing. It now removes those books too, the
  same way deleting a single book does, their file records, history, and the
  rest go with them, and if a particular book can't be removed, the
  confirmation message says how many failed rather than staying silent about
  it. Removing a root folder without that option is unchanged: the books stay,
  the files stay, the path is just no longer configured as a root.

- deleting several books at once ran the whole batch as one database
  transaction, so a single book failing partway through, most often one that
  had been through an audio-format conversion, silently rolled back every
  book already removed earlier in the same batch, while the results screen
  still reported all of them as deleted. Each book in a bulk delete now
  succeeds or fails on its own: a later failure no longer undoes earlier ones,
  and the count you're shown only ever reflects what actually survived. Two
  smaller mismatches with single-book delete came out of the same fix: bulk
  delete used to erase a book's Activity page history along with it and now
  keeps it, the same as deleting one book already did, and a release still
  marked as grabbed from a download client for a deleted book now has that
  in-progress state cleared instead of being left permanently unresolved.

- deleting an author, a series, or several books at once, with delete files
  turned on, cleaned up the book's now-empty folder by walking upward and
  removing empty parent folders, with nothing to stop it at the top. If that
  walk emptied out an entire root folder, it kept going past the root folder
  and up the real filesystem above it, stopping only at the first folder that
  wasn't empty or that it didn't have permission to remove. It now always
  stops at a configured root folder or a protected system path, and never
  removes either one itself.

- the same three delete paths above only ever removed the audio files they
  were tracking, so a book's `desc.txt`, `reader.txt`, `metadata.json`, or
  `.opf` file, sidecars ABM itself writes into the folder, was left
  behind, which meant the folder was never actually empty and the cleanup
  above never had anything to do. All three now clear those out too.
  `cover.jpg` is deliberately left out of that list: ABM only ever creates
  one when the folder doesn't already have one, so a `cover.jpg` already
  sitting there is just as likely yours as ABM's, and it's left alone either
  way. `.opf` is matched by extension alone, with no such check, one
  written by Calibre or any other tool in the same folder is treated the
  same as ABM's own and removed with it. Anything else in the folder ,
  notes, art saved under another name, anything you've added, is left
  alone.

- the Series page's own copy of the folder browser read a field the API has
  never returned, so it listed nothing at all, no matter which folder you were
  in. It now uses the same shared folder browser the book, author, and library
  pages already used.

- a book spread across multiple files took its title from whichever file's
  `title` tag happened to be read first, which, in a split book, names the
  part ("Track 07", "Part 08"), not the book, so the Library Import page
  offered parts as the books to match instead of the book's actual title. A
  folder holding more than one file now reads its title from the `album` tag
  instead, which is where ABM's own tagging already puts the book title, with
  any trailing disc or part marker (`Disc 2`, `CD-1`, `Part 3`, `Tape 4`,
  `Side 2`, `Pt. 2`, and the like) stripped off. A single-file book is
  unaffected, it keeps reading its own title tag as before. The same
  marker-stripping now also runs on a plain title tag, not just an album: a
  book re-merged from parts that kept the last part's title tag, showing up
  as, say, "White - Part 10", is cleaned up the same way. Nothing is stripped
  unless one of those markers sits at the very end of the text after a
  separator, so a title that legitimately contains the word "part," or simply
  ends in a number, is left alone.

- a book organized as `Author/Series/Vol 03 - 2017 - Title` had its title
  parsed as the literal folder name, volume and year included, instead of just
  `Title`, the folder-structure parser only recognized a bare year prefix
  (`2017 - Title`), not one preceded by ABM's own volume marker. It now strips
  both.

- a Library Import scan only recognized a folder as already in your library by
  matching it against the exact path a book was first imported from. A book
  that had since moved to a different folder, a root-folder move, a
  reorganize, anything that changed its location after import, no longer
  matched its own original folder, so scanning that folder again could offer
  it up as something new to import. The scan now checks a book's current
  location first, and only falls back to its original import folder if
  nothing currently lives there.

- an import session on the Library Import page was marked `imported` the
  moment its import task was queued, before the import had actually run, so
  a session whose import later failed, or was still running, already read as
  finished. Because the session list hides anything marked `imported`, that
  session disappeared from the page immediately, taking its only delete button
  with it. A session is now only removed once your library itself confirms
  every item it holds has actually landed there, not just because one
  import request came back error-free, so importing only part of a session
  and coming back for the rest later no longer wipes out the folders you
  haven't gotten to yet. If anything in it has failed, or simply hasn't been
  imported yet, the session stays so you can see what happened and pick up
  where you left off.

- a failed background task's status on the Tasks page showed a generic "Task
  returned success=False" whenever the handler hadn't set one specific
  top-level error message, which was most handlers, since they report
  failure through a structured list of per-item errors instead. That message
  now composes from that list when there is one: up to three of the actual
  errors, with a count of how many more if there were others, instead of a
  message that says nothing about what actually went wrong.

- **a bulk Audible download and a bulk add-and-download disagreed about what
  to do with a book you already had, and neither one asked.** Queuing a bulk
  **Download** re-licensed, re-fetched and overwrote every selected book
  unconditionally, including ones already sitting on disk, with no warning.
  Queuing a bulk **Add & Download** did the opposite and silently skipped an
  already-downloaded book, leaving no way to re-fetch one whose file had been
  damaged. Both actions now ask first whenever the selection includes books
  you already have, saying how many, and offering to keep the existing files
  or download them again and replace them. Keeping and replacing both go
  ahead with the rest of the selection either way; cancelling queues nothing
  at all.

  Both endpoints take a new optional `replace_existing` field that defaults
  to `false`. If you drive `download/bulk` yourself to force a re-download of
  books you already have, it now skips them unless the request sets
  `replace_existing` to `true`.

- **listing root folders with their unmapped-folder counts, Settings >
  Media Management, and the Library Import page's destination check, could
  take several seconds over a slow or network-mounted library.** It walked
  every folder one at a time, opened every leaf folder's metadata.json
  individually to check whether ABM had already claimed it, and re-proved
  every root's hardlink support from scratch by writing two throwaway files
  into it, on a real network-mounted library this took about 3.9 seconds.
  All three now happen together in one pass that reads several folders at
  once, and hardlink support is now checked only when a root folder is
  added, explicitly rescanned, or ABM restarts, rather than on every page
  view, cutting that same listing to about 0.65 seconds, with the same 397
  unmapped folders found either way. Right after upgrading, every root
  folder reports hardlink support as unknown until the one-time startup
  check finishes; it fills in on its own within moments.

- **a synced book's acquisition type was dropped whenever Libex supplied its
  metadata**, which is most books. Three things depended on that value and all
  three went quiet: the Audible Library footer's acquisition breakdown (Owned,
  Plus, Free Trial, Member Gift) never appeared, because it hides itself
  entirely once every book reads as unclassified; every book's Ownership badge
  read Unknown; and the Downloadable filter's Plus exclusion never actually
  excluded a Plus book, since an unclassified book looks exactly like a
  non-Plus one to that check. The value is now kept regardless of which source
  built the rest of the row. Nothing to do, an account's next sync, scheduled
  or run by hand, fills it in for every book already synced.

- **a book's purchase date could be quietly erased by a later sync.** Every
  sync wrote a purchase date for a book whether or not the item it had just
  read actually carried one, if Audible's response for that book omitted the
  date, or sent one in a shape that failed to parse, the stored date was
  overwritten with nothing anyway, on both the Libex and the Audible-API
  fallback path. It shows as the optional Purchase Date column on the Audible
  Library page (enable it under column options) and as a sort choice there, so
  a book that had a real date could silently go blank in both. A sync now
  leaves a book's stored date alone unless the item it just read supplies a
  usable one. This only stops the loss going forward, a date already erased
  by a past sync is gone, and only comes back if Audible's own record for that
  book carries it again on some future sync.

- **the column headings on the Calendar's Agenda list and the Interactive
  Search results table scrolled away with the rows**, instead of staying put
  the way a header row should. Both tables nested a horizontal-scroll wrapper
  inside the vertical-scroll one, which is what actually broke it, that
  combination puts the header's sticky positioning in the wrong scroll
  context, not just a missing style. Both now scroll on a single wrapper, and
  the Agenda view scrolls within its own area instead of scrolling the whole
  page along with it. The other Calendar views' layout is otherwise
  unchanged.

- **the Calendar had a blank gap between the toolbar and the
  navigation row below it, on every view.** A leftover duplicate spacer was
  reserving space for the toolbar twice. It's gone.

- **the Interactive Search popup didn't announce itself as a dialog to a
  screen reader, or say what it was for.** It now exposes itself as a
  dialog labelled by its own "Interactive Search" heading, so opening it is
  announced along with what it is rather than as an unlabelled change on the
  page.

- **a free member's Audible Original read as an unclassified "Unknown" book**,
  in both the Audible Library's acquisition breakdown and its own Ownership
  badge. Audible's type for one of these, `AudibleComplimentaryOriginal`, was
  never one of the ones ABM knew a label for, so it fell into the same bucket
  as a genuinely unclassified row instead of getting one of its own. It's
  labelled "Free Original" now, wherever the others are.

- **dragging the A-Z scrollbar on the Library page smooth-scrolled the whole
  way instead of jumping with your finger, and clicking a letter whose row was
  already on screen did nothing**, unlike Series, Authors and the Audible
  Library, which all jump instantly while you drag, only easing in once you
  let go, and always bring a clicked letter's row to the top of the view.
  Library now matches them on both counts.

- **the A-Z scrollbar could show the wrong letter on Library when sorted by a
  field not every book has** (Narrator, Publisher, and similar). Scrolling
  past books with nothing in that field kept the last letter shown instead of
  moving on, and scrolling back up could jump to a letter from further down
  the list. It now shows the nearest earlier book that actually has a value
  for the sorted field.

- **a success message could vanish a moment after it appeared.** Each one
  cleared itself on a timer that nothing cancelled, so when a second action put
  up a different message within a few seconds, the first action's timer took the
  new one down early, on Tags, Indexers, Download Clients, Connect and its
  custom messages, and General. The countdown now starts over whenever the
  message changes. The copied tick beside General's API key and the prompt to
  pick a series in manual import had the same problem when clicked twice in a
  row, and no longer do. General's error banner, a failed save, a failed API
  key regeneration or remote delete, or a password mismatch, now clears
  itself after 15 seconds, as it already did on Indexers, Download Clients and
  Connect. An rclone remote test's error now stays up for those 15 seconds
  instead of 5, and running a test no longer takes down an unrelated error
  that appears shortly after.

- **an indexer's tag restriction never actually saved.** Typing tags into an
  indexer's Tags field and saving looked like it took, the chips stayed in
  the field, but the save request never sent them, so the indexer stayed
  untagged and kept matching every series regardless of what you'd typed.
  Saving now sends the tags along with everything else.

- **signing in with a Spanish Audible account opened the wrong marketplace.**
  Spain's `market_place_id` was Amazon US's id, not Spain's, so the OAuth page
  ABM sent a Spanish sign-in to was the US one and the login could never
  complete correctly. Corrected to Spain's actual marketplace id.

- **Audible credentials touched disk unencrypted for a brief window, every
  time.** Adding an account, and every later decrypt of a stored account's
  credentials, which is to say every sync, download, and the legacy-key
  migration, wrote the plaintext auth data out to a temp file, read it back,
  and deleted it, instead of handling it in memory the whole way through. A
  crash or a permissions problem in that narrow window could have left a
  readable Amazon credential file sitting on disk. Nothing is written to the
  filesystem unencrypted at any point now. Adding an account also now checks
  that its freshly-encrypted credentials decrypt back correctly before they're
  stored, rather than storing them and only finding out something was wrong
  the next time they're used.

- **a dead Audible sign-in had no way back except deleting the account.** Once
  a stored login stopped working, every download against it failed with a raw
  `403 Forbidden` and the only recovery was removing the account outright ,
  which also dropped its whole library table and deregistered its device from
  Audible. An account needing re-auth now says so, in Settings and in the
  health page, and can be re-authenticated in place: sign in again, and the
  existing account keeps its library and picks up the new credentials. A
  returning sign-in is also checked against the account being re-authenticated,
  so it can't silently attach the wrong Audible identity.

  Six places that surfaced this and related Audible failures were returning
  the raw exception text into the API response, which could carry an Audible
  customer id or a fragment of a credential. All six now report only the
  failure's type.

  **`POST /api/audible/login/browser/start` and
  `/login/browser/complete` are gone**, replaced by `/api/audible/login/start`
  and `/login/complete`. Anything automating the old Add Account flow directly
  against those paths needs to move to the new ones.

- **editing a Language, Status, or Series Type auto-tag condition silently
  emptied its value the moment you touched the rule**, because the edit form
  compared an unwrapped value against JSON-encoded option values and never
  matched. A renamed rule could come back matching every book in your library
  if that condition was negated, with nothing on the tile showing it had lost
  its value. The form now reads and writes the same encoding, so opening a
  condition to edit it never changes what it matches.

- **an auto-tag condition with no value picked was silently accepted**, and if
  negated, matched your entire library rather than nothing. Empty values are
  now rejected when you save a condition (client and API both), and any
  condition already saved without a value is now treated as never-matching in
  either direction rather than matching everything when negated.

- **an auto-tag rule using a Root Folder or Tag condition with no value
  crashed the Apply action for every book**, not just the ones the broken
  rule covered. A rule like that is now skipped on its own and logged, and
  every other rule still runs.

- **an auto-tag condition with a value ABM didn't recognize was stored
  without complaint** and, negated, matched every book. It's now rejected at
  save time, and if one already exists from before, it's treated as
  never-matching rather than always-matching.

- **a Year, Runtime, or Rating condition never matched a book whose value was
  exactly 0**, because a 0 read as no value instead of a real one. It's now
  compared correctly.

- **corrected the Required checkbox's help text**, which described the OR
  logic backwards: a rule's optional conditions are ORed with each other
  across all types, not just within one condition type.

**If you're calling the auto-tag API directly:** creating or updating a

condition with an unknown condition_type or an empty value now returns 422

instead of silently accepting it. If you had automation relying on that being

accepted, it was matching your whole library by accident, this is the fix,

not a regression to work around.

- **a rename that failed on every file still said "Complete."** The toast's
  title only looked at whether there were any errors to list, not at the
  status the page had already worked out, so a rename where nothing succeeded
  read as done with a stray "4 failed" line underneath it. It now says
  **Failed**, the same as every other toast in the app already did for a total
  failure.

- **Progress and result toasts no longer go quiet, and they close on time.** A toast could stop showing for the rest of the page while its work kept running, and a toast fed by fast live updates could keep every other toast in the stack from auto-closing. Both are fixed.

- **typing a path that doesn't exist into the folder browser stranded you
  there.** Pressing Enter committed the typed text before anything checked it
  was real, so a mistyped path took over the breadcrumb and wiped the listing
  you had already browsed to, and Select then handed back the folder that
  doesn't exist rather than the one on screen. A rejected path now only adds an
  error above the listing that's already showing: the directory you were in, and
  in file-picker mode whatever file you had selected, stay put. Clicking the same
  folder again, or typing a working path, retries instead of doing nothing.
  Reopening the browser on a folder that has since gone shows the error over an
  empty list rather than the last folder's contents under the new name. Closing
  it drops everything it was holding, so a folder creation that hadn't come back
  yet can't leave the Create button stuck reading "Creating..." on the next open.
  Every screen that opens the folder browser gets this: root folders, library
  import, book and author edit, download clients, import lists, conversions and
  backups.

- **a metadata provider having a bad minute read as "this marketplace doesn't
  have it" instead of "the provider is struggling."** A 502 or 503 came back
  down the same path as a genuinely empty answer, so a lookup that walks the
  other marketplaces when a book, series or author isn't found in yours walked
  every one of them, hammering a server already behind, and then reporting
  nothing found. A provider error now stops that walk the same way a dropped
  connection already did, on the batch refresh path as well as the single
  author and series lookups, and it is never remembered: a blip partway
  through a scan no longer hardens into a wrong answer for the rest of it.

- **a book's or author's cover could keep loading from the external host for
  up to a day after it was set**, because only the scheduled 03:30 sweep
  cached a cover, anything added or changed between sweeps waited for the
  next one. A cover is now cached the moment it's set.

- **a cover chosen from search was recorded as coming from "url," never from
  the source it was actually found on.** Picking a cover found via iTunes or
  AudiobookCovers.com now records which one it was, instead of the generic
  "url" it was stamped with before.

- **an enabled recycle bin with no path saved deleted files permanently while
  every screen that showed the setting said they'd be recoverable.** An empty
  `recycleBinPath` meant two different things at once: the settings page showed
  the configured default folder, but every place that actually deletes a
  file, conversion's own delete-originals step included, read that same
  emptiness as "no recycle bin" and removed the file for good. Media Management
  now has its own explicit on/off switch for the recycle bin, and on/off is never inferred from whether a path
  happens to be filled in. The one-time migration that ships with this release
  repairs existing settings: an enabled bin with no path saved gets the
  configured default written in, and a media-management row saved before the
  switch existed is turned on, matching how it already behaved.

- **the Convert and Tags dialogs could show a previous book's choices.**
  Opening either one, changing something, and closing without applying left
  its state in place, reopening for a different book, series or author
  could still show the last operation, format, bitrate and Delete Original
  toggle chosen for whatever was open before, or Tags' previously seeded
  chips flashing briefly before the new selection's own tags loaded. Both
  dialogs now start fresh on every open.

- **a Convert dialog whose preview or submit failed said nothing.** The error
  went to the browser console only, so the button just stopped spinning with
  no explanation. Both steps now show what went wrong, the same way other
  dialog failures already do.

- **importing a multi-disc audiobook joined by hand from separate CD folders
  landed its tracks out of listening order**, because the files were only
  ever sorted by the number in the filename, and every disc's tracks restart
  at 1. Sorting now reads the disc off each file's own source folder, its
  tag when every folder's tag disagrees with the others, otherwise a
  CD/Disc/Part folder name when every folder's name does, otherwise the
  order the folders were joined in, then, for several discs merged flat
  into one folder with no subfolder per disc, the disc label in the
  filename itself; then the track off its own tag or its filename. A plain
  single-folder, single-disc import sorts exactly as before. The same
  import also recorded every file's original location as the first disc's
  folder even when a file came from a later one; each file now keeps its
  own source folder.

- **adding files to a library book, by hand, or by pointing at a folder to
  fill in a book's missing files, could destroy audio that had just been
  placed moments earlier, in the same import or a batch alongside it.** A
  book with several same-labelled files (for example three files each
  labelled "CD1" but ending in different track numbers) could all resolve
  to the same destination name; each new file then recycled the one the
  previous file had just placed, and the survivors could fail to save at
  all. Two queued rows adding files to the same book in one import batch
  had the identical exposure. One shared rule now decides every file
  placement everywhere it happens: a destination already on disk is either
  a genuine leftover from an earlier, separate run (recycled as before) or
  a file this same import batch already wrote (never recycled, that file
  is skipped and reported instead). Filling in a book's missing files a
  second time also numbers its new parts starting after the ones already
  there, instead of restarting at "Part 01" and colliding with them.

- **a background task's progress toast could get stuck spinning at 0%
  forever if the connection dropped while it was running**, a server
  restart mid-task, most commonly. It now gives up polling silently after a
  few failed checks in a row and shows an error with a Retry button instead,
  and it re-checks the task's status the instant the tab regains focus, so a
  completion that happened while the connection was down isn't missed. It
  also no longer resumes checking after the toast has been dismissed, and a
  slow-to-answer check for one task can no longer land on a toast that has
  since moved on to a different task, or been retried, so closing a toast,
  or starting a new task while an old one is still finishing up, can't be
  followed by a stray navigation or status update that belongs to the wrong
  task. Every page that shows a background task's progress gets this fix,
  since they all share the one toast.

- **series books now sort by their real position.** A book numbered 0 (a
  prequel, most often) sorted last instead of first, because the fallback
  for an unreadable position treated 0 the same as missing, Circle: Green
  and Alien: Covenant Origins were both book 0 and both landed at the end of
  their series. A position like "1.10" was read as 1.1 and sorted ahead of
  "1.2" instead of after it; positions are compared segment by segment now,
  the way a reader would. An unnumbered book sorted first, ahead of every
  numbered one, on the author page's series groups, Series, and manual
  import's bulk book assignment, the opposite of where it belongs. Sorting
  a series list, or Authors by year, in descending order used to pull every
  book or author with nothing to sort by back to the front along with
  everything else being reversed; it now stays last in both directions, on
  the library, the Audible library and Authors. The same reversal problem
  was there for every other column with a missing value, publisher,

- **the Queue failed silently.** Import Selected and Import Now ran a check of

  sends just the selected rows or the one row, and each failure shows a toast

- **Import on the Queue imports only the downloads you picked.** The import

- **a login dropped right after the server's clock was corrected backwards.**
  A token is stamped with the time it was issued, so a clock that stepped
  back a moment later made it look like it came from the future and it was
  refused. Checking a token now allows 10 seconds of clock difference, which
  also gives an expired token 10 seconds of grace.

- **Deletes and removals that failed quietly now say why.** Deleting from a book's
  page, a series, an author or the Authors list shows the delete task's result,

- **deleting books from the Library said "Complete" even when the delete
  failed.** A failed request or a server error still reloaded the page and
  showed a success toast, and a good delete reloaded the whole library just to
  show it. The delete now shows the queued task's own progress and result,
  including how many books it actually deleted, refreshes the library in
  place, and a rejected request shows the server's message.

- **Weekly Audible sync and Discover refresh ran a day late.** The day picker
  counts from Sunday but the scheduler counts from Monday, so every saved day
  ran the day after the one chosen. Saved days keep their meaning and now fire
  on the day they say. Custom cron schedules with a numeric weekday ran a
  day late too, so `0 3 * * 0` now fires on Sunday as in standard cron.

- **converting to Opus with a default sample rate of 22050 or 44100 failed.**
  libopus only takes 48000, 24000, 16000, 12000 and 8000, so ffmpeg refused
  the rate. Opus now uses the nearest supported rate at or above the one
  chosen (24000 or 48000) and says so in the log. The sample rate and channel
  settings also only accept the values the page offers, and a bad saved value
  loads as Auto.

- **the Audible page said the tokens could only be decrypted on this server.**
  They are encrypted with this install's secret key (APP_SECRET, or the key
  file ABM generates), so anyone with that key and the database can read them
  anywhere. The overview is now a short list of what the page does and how the
  sign-in is kept, in plain sentences, instead of one run-on block.

- **a chapter title with `=`, `;`, `#`, a backslash or a line break (or a carriage
  return) made ffmpeg
  throw away every chapter in the file.** Merging, Chapterize and the Audible
  download each wrote their own chapter file and only the Audible one escaped
  titles, and it turned a line break into a space. A missing or null title could also fail
  the job. All three now write it through
  one writer that escapes the way ffmpeg expects, so every chapter and its exact
  title come through. Chapterize also refreshes the tagged files' size, duration
  and chapter count, which stayed at the old values before.

- **a download that only partly moved into the library lost the parts that
  moved.** Every file is now staged next to its final name first and only
  swapped in once every one has arrived. If one fails, the parts already
  swapped in are put back where the download had them, any file an upgrade
  was replacing is restored, and the import is retried. The task log gets one
  line saying how many parts were put back and how many originals restored.
  An upgrade no longer overwrites the copy it is replacing until the new one
  is complete, and a partial download is no longer marked imported. If a part
  can't be put back, it stays in the book's folder as a hidden file ending in
  `.abmstage`, because it can be the only copy, and the error names it. While
  any `.abmstage` file is in a book's folder, imports into that folder stop
  with "Files left by an interrupted import are in the way. Recover or remove
  them, then retry", followed by the files. If you hit that, move the file
  back into the download or into the book's folder under its real name, or
  delete it if you don't need it, and the next import goes through. Stale
  `.abmtmp` files are swept after a successful import. A hardlink that falls
  back to a copy is now logged as a warning.

- **the Import Workbench's editions panel did not know whether a library book
  had files.** An edition you already own with no files on disk was shown the
  same as one you have in full. Each edition now says whether the book in your
  library has files (`library_has_files` on an edition's ownership, an

  edition results carry the edition's subtitle and Virtual Voice flag too.

- **an import that failed after the books were in still looked like a

- **losing contact with the server during a Workbench import dropped the

  done.

- **merging or splitting Workbench rows planned extra files against the old

  row are looked up again against the saved row.

- **closing the Import Workbench could lose your last edit.** An edit still

- **Manual Import could treat a shared downloads folder as the book's own.**

  stayed on the run that had just happened. It is now read from the schedule

- **the Series page's Missing and Wanted filters showed nothing.** A series

- **the reason Delete was disabled on Authors and Series only showed as a hover

- **an audio file's ASIN tag was trusted whatever it held.** A tag carrying

  it were one. It is now ignored, and the scan uses an ASIN from the file's

- **imported folders stayed in the Import Workbench list after an import
  finished.** Once the page had saved anything, the session it reloaded after

- **on a phone, the Import Workbench's folder and match counts ran off the

- **a split folder's files were each looked up under their file name**, so a

  books matched none of them, and every row needed a manual search. Each file
  is now looked up as the book its own tags name (title, author and series),

- **the Import Workbench's editions panel listed other books in the same
  series.** Opening Dune showed Dune Messiah and Children of Dune beside Dune's
  real editions, because the panel searched by title and kept everything that
  came back. It now lists only editions of the same book by the same author:

  the original title in square brackets, like "Seis de cuervos [Six of

- **A library import could match a book to a translation.** A Spanish edition
  listed as "La Vieja Guardia [Old Man's War]" was taken as the match for an
  Old Man's War folder, because its title contains the English one, and the
  English edition was never looked for. An edition in another language no
  longer ends the search, and between two equally good matches the English
  edition wins.

- The Workbench said "Show 1 editions"; it now says "Show 1 edition".

- **The Import Workbench crashed when ABM was opened over plain HTTP on a LAN
  address** ("crypto.randomUUID is not a function"). It now works over HTTP
  as well as HTTPS and localhost.

- **Saving settings with a value they don't accept failed with a server

  Options and root folders now answer 422 and name the field that was wrong.

- **An import could act on files outside the scan.** Add to Library trusted

  delete any file ABM can reach. Every path, and every file of a merged book,

  A library book an import names must also be one its row is linked to, so a
  hand-made request can't add a folder's files to some other book.

- **A rescan offered part of an already-imported merged book for import
  again.** After two folders were merged into one book and copied in, the
  second folder came back ticked for import, which would have added its files
  to the book a second time. A folder whose files are all already in a library
  book is now treated as already imported, the same as the folder the import
  started from, and Add refuses to import such files twice. A row whose match
  is a library book that already has files also no longer starts ticked.

- **Adding a folder to a book already in your library ignored FLAC, OGG,
  Opus, AAC and WMA files.** It now takes every audio format the rest of the
  import does.

- **Splitting a folder that was already in your library carried that library
  book onto every file**, so importing the split files would have added them to
  the wrong book. Split files now start with no library book of their own.

- **A merged book imported into a book already in your library took only one
  of its files.** Every file of the merged book is now added.

- **Merging rows kept the first row's keep-or-delete decision** and dropped the
  others' without a word. A merged book is now decided afresh.

- **refreshing a series, an author, or a manual import showed two near-identical
  completion toasts.** The page's own task-tracking toast and the backend's
  cross-client completion broadcast both told the initiating browser the same
  thing. The broadcast now carries the task id, so a client already showing its
  own toast for that task recognizes the broadcast as the same event and skips
  it, every other connected client still gets told.

- **A failure part way through a series or author refresh, a bulk edit's tag changes or a manual import could leave one book's change in place after the rest was rolled back.** Each step now commits or rolls back as its own unit, so a failure no longer undoes or keeps changes it should not, and the database lock is released between steps.

- **saving Conversions or Media Management settings could be submitted twice.** Their
  Save button stayed clickable while the save was running, so a second click sent the

- **a failed public-IP check on the General and Audible settings pages read "Unknown".**

- **an import list's MAM session cookie was never saved.** The Import Lists dialog

- **The local-address login bypass missed IPv6 and dual-stack clients.** Behind a

  never matched the private ranges, so it was asked to log in. Mapped addresses are

- **Deleting a book could move a series' cover to a different book.** The
  series list and Series Books picked the cover from whichever book happened
  to still be owned, rather than always the series' first book, so deleting

  shows the same cover on Series Books and the author page as it does in your
  library, rather than the catalog's copy.

- **Deleting a book that had an author assigned could fail with a server
  error** instead of deleting the book.

- **If you call `DELETE /api/books/{id}` directly:** `files_deleted` only
  echoed whether you asked for the files to be deleted, not whether any

- **Deleting a book, series or author removed unrelated series and authors.**
  The cleanup after a delete removed every series and author in the library
  with no books, not just the ones the delete touched. It now removes only
  the series and authors the delete itself left with no book in your library
  (a wanted book still counts), along with their catalogs. A book an Audible
  download or a library import is still bringing in counts too, until that
  task finishes or fails; the daily 04:00 task cleanup then removes any
  series or author the task brought no book into. If a running download or
  import can't be read, that cleanup removes nothing until it can, rather
  than risk the catalog of a book still on its way. An author is never removed if you added them

  that isn't the last of its series or author only marks it not in your

- **A series page for a series that no longer exists showed an empty page
  with all its actions still live.** It now says "Series not found", the
  same way the author page already did.

- **A deleted book still showed as owned on the author page and the
  calendar.** Deleting a book now marks it not owned in every catalog.

- **A bulk delete's progress could stall for close to 25 seconds with
  "database is locked" in the log.** The whole batch ran as one open write
  transaction, holding SQLite's write lock for the entire run while
  progress updates on a separate connection queued behind it. Each book,
  author, or series now commits on its own, releasing the lock between
  items.

- **Import-list cleanup's "remove" actions left orphaned authors and series
  behind.** Removing a book this way skipped the orphan sweep every other

- **Syncing Audible accounts from Audible settings gave no feedback.** The sync ran in

- **importing a large library was slow enough to feel stalled.** Matching ran
  one book at a time against Libex, opening and tearing down a connection for
  every search. It now looks up three books at once, reuses one warm
  connection per worker instead of one per request, and fetches every
  folder's Audible ID in a single batched call instead of one apiece. A
  100-book import that used to take close to three minutes now finishes in
  under a minute.

- **a book whose folder names its Audible ID still searched its whole series
  after the ID had already found it.** That search could never change the

  there: two such books match in about 0.3s with one Libex call, down from

- **a lookup that crashed partway through, a dropped connection, a bad
  response from Libex, used to come back indistinguishable from a book that
  was honestly searched and found nothing**, landing silently in "No Match."
  It's now its own "Error" status, counted on its own in the import summary,

- **A series or author refresh could mark it up to date, and report success,

  author's full book list failed because Libex itself was unreachable, the

  an error in the result instead, and the series or author is retried on the

  refresh, an author refresh, adding an author, a library import, or adding

  a partial catalog failure still reports success, same as a partial book

- **A library scan with multiple root folders created an empty folder for the same

- **An author page's "Refresh Catalog" always claimed success**, even when the

### Security

- **rename and delete by path, the library migrate endpoint, and author/series
  bulk relocation could reach outside every configured library folder** ,
  including the database file and the auto-generated encryption key. A book's
  folder move already checked both ends against the configured roots, but
  trusted any `old_path` it was given, so it could be pointed at another
  book's folder; it now also requires `old_path` to be the book actually
  being moved, and returns 404 for a book that doesn't exist. All of these
  resolve symlinks and refuse anything that isn't strictly inside a
  configured root folder, through one shared check.

- **the generic system-settings endpoint is gone.** It read and wrote any
  stored setting by key with no schema, and was the only path that could
  ever return the security settings' password hash to any authenticated
  caller, including an API-key caller, or write a malformed setting past
  every validator meant to catch one. Import List's clean-up level and RSS
  sync interval, its only real callers, now go through a typed endpoint with
  a proper Save button instead of saving on every keystroke.

- **an unauthenticated request could read any file the ABM process can
  read**, including the database and the auto-generated encryption key
  file, by asking the app for a path like `/../../etc/passwd`. The route
  that serves the frontend for everything that isn't an `/api/...` request
  is deliberately excluded from the login check, so the frontend can
  handle its own redirect to the login page, but it never confirmed the
  resolved path stayed inside the frontend's own build directory before
  serving it.

- **the backup download, delete, restore, and remote-export endpoints
  built a path straight from the requested filename with no containment
  check at all.** All four now resolve through one shared check before
  ever touching disk.

- **the bare `/api` endpoint (no trailing slash) returned the app name and
  version to anyone, logged in or not**, because the route detection
  behind the frontend fix above let it past the login check too. It now
  requires the same login as every other `/api/...` route.

- the log viewer already confirmed a requested path stayed inside the logs
  directory by path segment rather than a naive string prefix, so it was
  not open to the sibling-directory trick the other three endpoints above
  were, but a symlink loop under the logs directory raised an unhandled
  error instead of a clean rejection. Fixed, and all four of the checks
  above now share one path-containment helper instead of four separate
  copies of the logic.

- **a failed attempt to read the Security settings used to hand back a
  fresh, made-up API key and a login policy that skips authentication on
  the local network**, so the very next Save could silently re-enable that
  bypass and rotate the key without anyone asking for either. A read
  failure now shows an error instead of fake settings, saving no longer
  accepts an API key at all, only the Regenerate button can set one, and
  a key is never generated just from opening the Settings page.

- **a new install could end up with a blank API key**, nothing minted one
  until the Regenerate button was clicked, so a caller relying on it out of
  the box got an empty string. Initial setup now generates a strong key and
  stores it encrypted, the same as Regenerate does, and an existing install
  whose stored key is still empty gets one filled in automatically on the
  next startup.

- **The website links on Import Lists, Indexers and Download Clients cards now open only http and https addresses.** Anything else, such as a `javascript:` or `data:` link, or an address with no scheme, shows no link.

- **SFTP/SCP backup export now checks the server's host key.** The first
  connection trusts the key and saves it, with its fingerprint shown on the
  target. A changed key is refused before the password is sent, until I forget
  the saved one on that target. Changing a target's host, port or type also
  forgets it.

- **The API docs pages load without contacting any third party.** `/api/docs`
  and `/api/redoc` used to have your browser fetch Swagger UI and ReDoc from
  jsdelivr and fonts from Google, which handed those hosts your IP address and
  broke the pages offline. The Docker build now downloads pinned, checksum-
  verified copies and ABM serves them itself, and the pages' security policy
  allows only ABM's own origin. A source checkout needs
  `sh scripts/fetch_docs_assets.sh` once, or the docs pages come up blank.

- **Restoring a backup asks for your current password.** A restore swapped in
  the archive's sign-in method, username, password, API key and trusted networks
  without asking for anything, so a hand-made archive could turn authentication
  off, and one with no sign-in settings sent the app back to first-run setup.
  Restoring now needs your current password, and the restore message tells you
  when the backup's sign-in settings weren't applied; they are left alone unless
  you opt in to restoring them. Only encrypted backups can be restored.
  Unencrypted backups from versions before 0.14 are no longer accepted (they
  couldn't be restored on a current install anyway), so make a new backup from a
  current install. A backup that can't be restored without resetting the app to
  first-run setup is refused before anything is replaced. API change: both
  restore endpoints return 403 without the current password when one is set, and
  the upload endpoint returns 400 for a plain ZIP (restoring one by name answers
  with `success: false` and the reason).

- **Only one restore runs at a time.** Pressing Enter twice, or starting a
  second restore from another tab, could run two restores over the live
  database at once. A second restore is now refused with
  "A restore is already running." (HTTP 409).

- **The image's rclone is a pinned, hash-checked release.** The Docker build
  downloaded whatever rclone was current at build time, with no check on what
  arrived, so two builds of the same commit could ship different rclone
  binaries and a tampered download would have gone in unnoticed. The build now
  fetches rclone 1.75.2 and fails unless the zip matches the sha256 from
  rclone's signed checksum file. 1.75.2 is a security release: it stops the
  WebDAV headers option and the B2 account token from being sent on to another
  host after a redirect, fixes the pCloud OAuth setup accepting a callback
  without its state check, and is built with a Go release that fixes a batch of
  HTTP and TLS CVEs.

- **A website or indexer URL has to be an http or https address.** The website
  URL on an import list or an indexer, and an indexer's base URL, took any
  text, so a `javascript:` or `data:` link could be saved and then clicked.
  They now refuse anything but an absolute http:// or https:// URL with a host
  (so also `file:`, `ftp:`, `gopher:` and a bare `example.com`) with a 422
  that names the field; a Prowlarr sync with such a base URL gets a 400.
  Empty is still fine for the website URL. A link already saved with a bad
  scheme still shows, but saving that item again fails until the link is
  fixed or cleared. The error on the page now says why the value was refused
  instead of a generic failure.

- **The security logs can't be deleted through the API any more.** Deleting a
  log file or clearing all logs could remove `logs/security/`, the audit trail
  fail2ban reads, for any logged-in caller and for anyone on the local network
  without a login. Deleting a security log now answers 403, clear-all leaves
  that folder alone and says how many files it skipped, and the path is
  resolved first so `../` or a symlink can't get around it. Every refused
  attempt goes into the security log.

- **Requests through a reverse proxy ABM doesn't trust no longer count as
  local-network requests.** Behind a proxy on the same Docker network, every
  request arrived from a private address, so with "local addresses skip sign-in"
  on (the default) anyone on the internet was signed in as an admin, on the
  WebSocket as well. A request that carries proxy headers from an address that
  isn't in TRUSTED_PROXIES now has to sign in, and ABM logs a warning naming
  that address once. Through a trusted proxy, only the client address it passes
  along counts, and only if that address is local; a trusted proxy that passes
  none is treated as not local. The security log's denial now says which of
  these it was. **Action needed if you run a reverse proxy:** set TRUSTED_PROXIES
  to your proxy's address to keep skipping sign-in on your LAN. A proxy on the
  same host needs `TRUSTED_PROXIES=127.0.0.1`; until it's set you'll be asked to
  sign in. Direct connections without proxy headers behave as before. uvicorn no
  longer rewrites the client address from X-Forwarded-For itself, so
  TRUSTED_PROXIES is the only thing that decides.

- **A reverse proxy that sends no forwarding headers no longer signs everyone
  in.** Some proxies pass requests on without X-Forwarded-For or X-Real-IP, so
  ABM saw a private address and, with "local addresses skip sign-in" on (the
  default), let anyone reaching the proxy in as an admin. ABM now catches this
  two ways. A same-origin browser request whose origin isn't the address it
  reached ABM on marks that address as a proxy: it is remembered across
  restarts, per address (an IPv6 /64 counts as one), in a short list of recent
  addresses rather than a global switch, and requests from it have to sign in
  from then on. A request addressed to a public name or IP makes just that one
  request sign in; it isn't remembered, so one stray request can't lock out
  everyone behind a shared Docker address. Names ending .home, .box, .lan,
  .local, .internal, .localdomain or .home.arpa, and ABM's own addresses, count
  as local. System > Status shows a "Reverse Proxy" warning with the fix (for
  a public name it stays for an hour), and Settings > General > Security has a
  "Detected Reverse Proxies" row where you can clear what was remembered, after
  confirming your password. /api/health stays public, so the Docker
  healthcheck is unaffected. **Behaviour change:** an address in
  TRUSTED_PROXIES that sends no X-Forwarded-For or X-Real-IP is no longer
  treated as local, so if you put 127.0.0.1 in TRUSTED_PROXIES and also open
  ABM directly on the host, that direct visit now asks you to sign in. Fix the
  proxy to send X-Forwarded-For, or open ABM from another local address.

- **Request bodies are capped.** Any one client could send a multi-gigabyte body
  and run the single worker out of memory, with no credentials needed on the
  local network. Every request now has a 10 MiB cap, checked against the
  declared length and against the bytes actually received, so a chunked body or
  an understated length is stopped too; the middleware itself answers 413 and tells the route the client went away,
  so no route's own error handling can turn it into a 400 or 500. Backup restore keeps
  its 500 MB and a cover upload gets 15 MB, and the cover upload also stops
  reading at its cap instead of buffering the whole body first.

- **Every remote cover download now goes through one guarded fetcher.**
  Writing `cover.jpg` into a book folder, the cover Audible downloads embed,
  and the cover attached to Pushover, Pushbullet and email notifications each
  had their own download. The `cover.jpg` and Audible ones followed redirects
  without checking where they led, so a public cover URL could redirect ABM to
  an internal address such as the cloud metadata service, and neither capped
  the size or checked the body was an image. The notification one read the
  whole body before checking its size. They now all use the
  same fetcher as custom covers: every redirect is re-checked, the body is
  capped at 15 MiB, only images are accepted, and the image is re-encoded
  before it is written or sent. Every cover download, custom covers and the
  cover cache included, now goes through the outbound proxy when one is set
  (Settings → General); before, only `cover.jpg` did.

- **Cover and download URLs from outside can no longer reach the shared
  100.64.0.0/10 range.** That range (carrier-grade NAT, and where Tailscale
  peers live) was not treated as internal, so a cover URL or a notification
  upload URL could point at it. Every address that is not publicly routable is
  now refused for those. URLs you configure yourself, such as a notifier or an
  RSS feed, can still use it.

- **Indexers on your LAN or Tailscale work with Blackhole and torrent
  pre-fetch.** A download link from Prowlarr, Jackett or a private indexer on
  a LAN or Tailscale address was refused when ABM fetched it itself (the
  Blackhole clients, and reading a torrent's hash before sending it). A link
  on the configured indexer's own host is now allowed on the LAN and the
  shared range. Loopback, link-local and the cloud metadata service are still
  refused, and a link to any other host must still be public.

- **The calendar feed escapes book titles.** A title, series or author name
  with a line break could add its own lines to the `.ics` feed, such as an
  alarm or an attachment. Text in the feed is now escaped the way the
  calendar format requires.

- **The Content-Security-Policy is now on by default.** ABM sends the
  `Content-Security-Policy` header on every response without being asked,
  which limits what a page can load or run to ABM's own scripts and styles,
  its own API and websocket, and cover images over HTTPS. Set
  `SECURITY_HEADERS_CSP_ENABLED=false` to turn it off; that does not allow
  framing, since `X-Frame-Options: DENY` is always sent. The API docs at
  `/api/docs` and `/api/redoc` get their own policy that allows exactly the
  Swagger UI and ReDoc files they load, so they still work with the policy on.
  The setting only ever lived in the environment, so an install that never set
  it gets the header now, and one that set it to `false` keeps it off.

- **The indexer list no longer sends API keys and cookies to the browser.**
  `GET /api/indexers` returned every indexer's plaintext API key and MAM
  cookie. It now returns `has_api_key` and `has_cookie` flags instead, the
  same way download clients already did. The proxy password and the export
  target passwords and S3 secret keys were also returned by their settings
  endpoints and are now reduced to `has_*` flags. The Prowlarr sync endpoint
  (`GET /api/v1/indexer`) now returns `********` for an indexer's API key, as
  Sonarr does, and sending that mask back keeps the stored key. On every one of these, a
  blank secret on save keeps the stored value instead of replacing it, and
  Test still uses the stored one. A blank API key sent to an indexer or a
  blank password or API key sent to a download client used to wipe the
  stored value; that is fixed. Export target and proxy secrets are still
  stored unencrypted in the settings table.

- **A webhook notification's Custom Headers are now a secret.** They often
  carry an `Authorization` token, but were stored in plain text and sent back
  to the browser with the rest of the form. They are now encrypted with the
  webhook's other secrets, come back blank when you edit the notification,
  and are kept when you save with the field left blank. Headers saved before
  this change are hidden too, and move into encrypted storage the next time
  you save that notification. Custom Headers entered in the form also never
  reached the webhook: they were sent as raw text, which failed the send.
  They are now read as the JSON object the field asks for, and saving
  anything else is refused.

- **A stored secret is no longer sent to a different address.** Testing or
  saving an indexer, download client, notification, import list, export
  target or the proxy with its API key, cookie, password or token left blank
  kept the saved one even when the address changed, so the stored secret
  could be pointed at any host typed into the form. A blank secret now only
  keeps the saved one while the address, port, TLS setting and type stay as
  they were saved; change any of them and the secret has to be entered again,
  which the form now says in the secret field. Prowlarr sync follows the
  same rule when it sends the masked key with a new URL. An address that
  different HTTP libraries read as different hosts (a backslash, a tab, or a
  user name before `@`) never counts as the saved one, and indexer URLs and
  API paths and download-client hosts that contain one are refused, as are
  outbound URLs checked before any fetch. An indexer API path typed without
  its leading `/` (`api`) is saved as `/api`, and an Apprise notification
  whose URL is not a web address can still be renamed or tested without
  re-entering it.

- **Saving an export target with a blank password or S3 secret key no longer
  stores it empty.** A blank secret only keeps the stored one for a target
  that already exists; a new target with a blank password or secret key is
  now refused instead of saved without one.

- **The real-time connection (`/api/websocket`) accepted anyone.** It carried
  job, scan and toast events with no login and no check on which site opened
  it, so any web page you visited could connect through your browser and read
  them. The connection now needs the same credentials as the rest of the API
  (session cookie, `Authorization: Bearer`, `X-Api-Key` or `?apikey=`), and a
  browser connection must come from ABM's own address, the `X-Forwarded-Host`
  set by a proxy listed in TRUSTED_PROXIES, or a domain listed in the CORS
  allowed domains. The local-network login bypass no longer lets another LAN
  site in. A refused connection is turned away before it opens. The socket now
  reconnects as soon as you log in and closes when you log out. Subscribing is
  limited to the `conversions` and `library` channels. The debugging endpoint
  `POST /api/websocket/test-broadcast`, which let any caller push a toast to
  every open tab, is removed.

- **Another web page could make your browser change ABM's settings.** A page on
  any site, including another app on the same machine or LAN, could submit a
  request to ABM, and your browser would attach your login cookie, or the
  local-network bypass would let it straight in. A request that changes
  something (`POST`, `PUT`, `PATCH`, `DELETE`) and is allowed by the login
  cookie, the local-network bypass, or authentication being off must now come
  from ABM's own address, the `X-Forwarded-Host` set by a proxy listed in
  TRUSTED_PROXIES, or a domain listed in the CORS allowed domains. The browser's
  `Origin` header decides, or its `Referer` when `Origin` is absent; a request
  with neither is refused with 403 `cross_origin_rejected`. Requests carrying a valid
  `X-Api-Key`, `?apikey=` or `Authorization: Bearer` are not affected. A script
  that changes things over the local-network bypass without a key must now send
  the key. Cross-origin access (CORS) is now granted only to the CORS allowed
  domains; every private-network address and the fixed set of localhost ports
  are no longer allowed to make credentialed requests and read the answers.
  The Content-Security-Policy's `connect-src` is narrowed to `'self'`. With
  that policy switched on, the early theme script no longer gets blocked, and
  the offline cache now leaves cover art from other sites to the browser.

- **A log message that failed to format could write a password in the clear.**
  When a message's arguments didn't match its format string, the log
  redaction step skipped it entirely, so a credential in its text reached the
  log file unmasked. It is now masked either way.

- **the API key is fully hidden in Settings → General, and sensitive security
  changes ask for your password.** The settings page shows no character of the key
  at all, not even its last few digits, `GET /api/settings/general/security` now
  returns only `has_api_key`, a yes/no. Showing or copying the full key,
  regenerating it, and saving the Security section all ask for your current
  password first. A wrong or missing password is refused and written to the
  security log, in the same format as a failed login, so fail2ban can act on it.
  Other General settings still save without a password. The unused
  password-check endpoint (`POST /api/settings/general/security/verify-password`)
  is removed. Any script that read the plaintext key from
  `GET /api/settings/general/security` must now call
  `POST /api/settings/general/security/api-key/reveal` with
  `{"current_password": ...}`.

- **an API key that can't be decrypted is reported instead of passed off as the key.**
  If APP_SECRET changes after the key was stored, Settings → General now says the key
  can't be decrypted and asks you to regenerate it. Revealing it returns an error
  rather than the encrypted text, and no API key authenticates until you regenerate.
  The startup pass that encrypts leftover plaintext secrets also no longer
  re-encrypts a value that was encrypted under a different APP_SECRET.

- **A crafted request path or header value could forge a line in the
  security audit log and other app logs.** A path like
  `/api/x%0aFORGED LOG LINE` arrives with that `%0a` already decoded to a
  real newline, and a username carrying `%E2%80%A8` arrives as U+2028 (the
  Unicode line separator), both land in a log line unescaped, and
  `str.splitlines()` and many log viewers treat either as starting a new
  line. Every file-backed logger in ABM (the security audit log, the main
  app log, and the per-job/per-operation logs) now escapes C0 and C1
  control characters (`\x00`-`\x1f`, `\x7f`-`\x9f`, including `\n`, `\r`,
  `\t`) and the Unicode line and paragraph separators (U+2028, U+2029) out
  of every log line, as `\xHH`/`\uHHHH`. This escapes those specific
  characters; it is not a general input sanitizer.

- **The client address read from a trusted reverse proxy wasn't checked.**
  Behind a configured trusted proxy, the client address taken from
  X-Forwarded-For or X-Real-IP was used as raw header text, so a hop like
  `203.0.113.9:51234` (some proxies append `:port`) or junk text ended up in
  logs and address checks as-is. A trailing `:port` is now stripped and the
  hop must parse as a real IP address; if it doesn't, the client is treated
  as unknown (never local, never the proxy's own address).

- **a stored credential that can't be decrypted is no longer sent as the credential.**
  If APP_SECRET changed after an indexer API key or MAM cookie, a download-client
  password or API key, an import-list cookie, or a notification's secrets were saved,
  ABM used to send the encrypted text to the indexer or client as if it were the real
  value, and a notification quietly went out without its secrets. It now treats the
  value as unreadable and doesn't contact that indexer, client or notification service
  at all. The card and edit dialog in Settings → Indexers, Download Clients, Import
  Lists and Connect, Test, and System → Status all say the stored credential can't be
  read and ask you to re-enter it. Saving a row for any other reason keeps the stored
  value exactly as it was, so restoring the old APP_SECRET makes it readable again. The
  log names the table and column, never the value.

- **an import list's Test and scheduled sync now fetch the feed the same way.** Both
  refuse a feed on a loopback, link-local or cloud-metadata address, while a feed on
  your LAN (including a Docker network or rss-bridge) still works. Test now sends the
  list's cookie and judges the feed by parsing it rather than by its Content-Type, so
  a valid feed served as text/html passes. Test on a list whose cookie can't be read
  no longer marks it healthy, and one list failing unexpectedly no longer stops the
  others from syncing.

- **removing a download from the Queue no longer echoes the client's raw error.** A
  failed remove now reports the same short failure category as Test and Grab, so a
  client URL or credential in the underlying error can't reach the page.

- **urllib3 updated to 2.8.0**, fixing three published advisories in the HTTP library
  ABM uses for outbound requests: a proxy TLS-settings override and two ways a
  malformed chunked response could hang or exhaust memory.

- **Starlette updated to 1.3.1**, fixing two published advisories in the web framework
  under ABM's API: a crafted request target or Host header could make a request's URL
  report a different path than the one being routed, and an oversized or field-heavy
  URL-encoded form had no size limit.

- **pydantic-settings updated to 2.14.2**, fixing a published advisory in the library
  that loads ABM's settings: a symlink in a secrets directory could make it read a
  file outside that directory. Settings still load from `.env` and environment
  variables exactly as before.

- **pyasn1 updated to 0.6.4**, fixing three published advisories in the ASN.1
  decoder behind the Audible client's RSA signing: crafted input could make it
  spend excessive CPU or memory on object identifiers, long tag IDs, or large
  real-number exponents.

- **oauthlib updated to 4.0.0**, fixing two published advisories in the OAuth
  library the notification sender pulls in: JSONP callback injection on the token
  revocation endpoint and a timing leak in the PKCE code check. Both are in
  oauthlib's server side, which ABM never runs.

- **cryptography updated to 50.0.2**, fixing four published advisories in the library
  behind ABM's encryption at rest and encrypted backups: a timing leak in PKCS#7
  decryption, two certificate-verification flaws, and the vulnerable OpenSSL bundled
  in older wheels. Stored secrets and backups encrypted by earlier versions still
  decrypt unchanged.

- **PyJWT updated to 2.15.0**, fixing thirteen published advisories in the library
  that signs and checks login tokens, including algorithm-confusion and key-type
  checks, non-Base64URL signatures being accepted, and a slow-regex denial of
  service.

- **aiohttp removed**, an unused dependency, along with the seven packages only it
  pulled in, which clears its 14 published advisories from the install.

- **paramiko updated to 5.0.0**, removing SHA-1 as an allowed RSA signing/verification
  algorithm in the SSH library ABM uses for SFTP/SCP backup export.

- **The login check no longer trusts a rebuilt request path.** It reads the path straight from the route and denies anything that is not a plain, already-decoded path, such as a relative path, a doubled slash or a `.` or `..` segment. No public path changes: the frontend, its static assets, the login routes and `/api/health` stay open, and API keys and the local-network bypass are unaffected.

- **AAXC decryption key and IV are masked in logs.** The ffmpeg command built for an Audible download carried `-audible_key` and `-audible_iv` in plain text into the debug log and the download log; log redaction now masks both values.

- **Logs mask more Audible secrets.** ADP tokens, private keys, activation bytes, cookies, customer info and authorization values no longer appear in log output.

- **HTTP Basic credentials are now verified.** With Basic authentication selected, the username and password the browser sends were never checked against the account, so the browser prompt could not sign anyone in. Requests and WebSocket connections now succeed only with the configured account's credentials. Scripts that use Basic for POST, PUT, PATCH or DELETE calls need an Origin header with ABM's own address, or should use an API key instead. The security settings now reject values the app does not recognise.

- **Cover cache and cover embedding validate images before decoding them.** A cover downloaded by the cover cache, a folder cover file and art read from an audio file went to Pillow with no format, size or decompression-bomb check, and a decompression bomb in the cover cache stopped the whole caching run instead of counting as one failed cover. They now pass the same check as an uploaded cover (JPEG, PNG or WebP, at most 5000 pixels a side), an image that fails it counts as a failed cover and leaves nothing on disk, and the cached original is always a real JPEG. A folder cover that fails the check is skipped and the book's remote cover is used instead.

- **Import list feeds can no longer redirect ABM to an internal address.** Each redirect hop is now checked like the configured URL, capped at five, and the list's cookie is only sent to the host it was set for. A feed that redirects somewhere unsafe now fails as an unsafe URL.

- **Passwords written as `user:pass@host` are masked in logs even without a `scheme://`.** Log redaction only masked credentials inside a full URL, so a bare `user:password@host` went into the log file as plain text. It is now masked, including a password that contains `@` and an IPv6 host, and so is a lone `token@` in front of an IP address or a `host:port`. Email addresses and `git@github.com:` style addresses are left visible.

- **API error responses no longer repeat internal error text.** A failed request now returns a fixed message that says what could not be done, and the underlying error goes to the server log only, so file paths, host names, credentials and database details no longer reach the browser. This covers failed saves, deletes and scans across the settings, library, series, author, import, notification and indexer pages. The indexer search results list no longer shows the raw error from an indexer, and the proxy test no longer shows the proxy address. Saving Discover settings with a day of month, hour, minute or other value out of range now returns a 422 validation error, as the Audible settings do, instead of a 400, and so does an explicit null there. A few failures that used to return 400 for server-side faults now correctly return 500, and bulk status and monitor requests with an empty `book_ids` list now return 422 instead of succeeding with nothing changed. Error messages are now fixed text, so anything that matched on the old message text, or expected a 400 from those failures, needs updating.

- **A proxy that cannot be used stops the request instead of going direct.** When the proxy is on but its settings cannot be read, or its hostname is empty, requests now fail with a clear message instead of going out on the direct connection.

- **Credentials with a longer name are masked in logs.** Log redaction only caught a credential key with one word in front of it, so a value such as `download_client_password` or `my_app_api_key` went into the log file as plain text. Those are now masked, along with brace-wrapped values such as `adp_token`, PEM private key blocks, credentials embedded in a URL and the Cookie header.

- **Task errors and messages no longer carry raw exception text.** A failed task, a per-item error on the Tasks page, an Audible download activity entry and a library scan message now show the error with its SQL, query parameters and credentials removed instead of the raw exception string.

- **Rejected requests no longer echo what was submitted.** A malformed request now gets a 422 that names the field and the problem but never repeats the value, so passwords, API keys and cookies no longer come back to the caller or land in response logs.
